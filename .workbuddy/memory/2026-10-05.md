# 2026-10-05 —— 程序中文名（逐鹿 图片编辑器）+ 应用图标 + exe 图标

## 这一轮做了什么

用户给了三项要求：① 中文名 **逐鹿 图片编辑器**（英文名保持工程名 `ZlPhotoEdit`）；
② `resources/logo.svg` 设为**应用程序图标**；③ `resources/logo.ico` 加入 **Windows
资源编译**，当 **exe 的图标**。

## ★ 一句话结论：程序名与"应用标识"是两件事 ★

| | 给人看（可改） | 存储用（**一旦发布不许改**） |
| --- | --- | --- |
| 值 | `appinfo::displayNameCn()` = "逐鹿 图片编辑器" | `kOrganizationName="ZlStudio"` / `kApplicationName="ZlPhotoEdit"` |
| 用在 | 窗口标题 / 任务栏 / "关于"框 / 退出提示 | **QSettings 的路径** `HKCU\Software\ZlStudio\ZlPhotoEdit` |

**改 `kApplicationName` 的后果不是"改名"，是 QSettings 换键 → 用户全部设置"消失"。**
中文名只许用于显示。自检里有一条断言逐字盯着这件事。

## 新增文件

- `src/ui/AppInfo.{h,cpp}` —— 名称与图标的**唯一来源**：
  - `displayName()/displayNameCn()/displayNameEn()`
  - `titleSuffix()` → `"逐鹿 图片编辑器 (ZlPhotoEdit)"`；名字相同时**不**拼成 `"X (X)"`
  - `windowTitleFor(fileName, zoomText)` → **拼法只有这一处**（以前 `" - ZlPhotoEdit"`
    在后缀两处各写一遍，改中文名漏一处就是"标题中文、后缀英文"的拼接怪）
  - `windowIcon()` —— 自己用 `QSvgRenderer` 光栅化 `:/logo.svg`（不用 `QIcon(":/…")`，
    理由同 `IconLibrary`），8 档尺寸 + 每档 2×
  - `windowIconPixmap(px)`（自检量像素用）、`exeIconSourcePath()`、`hasExeIcon()`
- `resources/app.rc` —— `IDI_ICON1 ICON DISCARDABLE "logo.ico"`（**无 BOM、LF**，
  属构建脚本类；只有 `.cpp/.h/.md` 要 BOM）

## 改了什么

- `src/main.cpp` —— `QApplication` 之后加**步骤 2.5**：`setWindowIcon(appinfo::windowIcon())`，
  失败时 `qWarning` 说一句人话（图标失效是**静默**的，必须留痕）；头部顺序注释同步。
- `src/ui/MainWindow.cpp` —— `setWindowTitle(appinfo::titleSuffix())`；
  `updateWindowTitle()` 重写成走 `windowTitleFor()`（删掉两处手写后缀）；
  ★ 构造里**再设一次窗口图标** ★ —— 因为 `main.cpp` 那层是"进程级默认值"，
  而 `MainWindow` 被**别的宿主**创建时（自检截图工具就是）那条路没人走。
  实测：截图工具原先报"窗口图标是空的"，补这一句后变"否"。
- `src/ui/MainWindowActions.cpp` —— 退出提示 / `关于 …(&A)...` / `QMessageBox::about`
  标题 + `<h3>` 全走 `AppInfo`（注意 `tr("<h3>%1</h3>…").arg()` 的**参数序号
  整体后移一位**，加了 `%1` 之后 Qt 与版本字符串变成 `%2/%3`）。
- `resources/gen_icons.py` —— ★★ **新增 `FIXED_RESOURCES` 表** ★★
  （`["logo.svg"]`）。**qrc 是 `open(..., "w")` 整体重写的生成物**，
  用户手加的那一行活不过下一次生成、而且**静默消失** → 凡要进 qrc 的文件
  要么由脚本生成、要么登记在这张表里。实测重跑脚本后 qrc 仍 88 行、逐字节幂等。
- `.pro`：`win32 { RC_FILE = resources/app.rc  \n  DEFINES += ZLPE_HAS_EXE_ICON=1 }`；
  SOURCES/HEADERS 补 `AppInfo.{cpp,h}`。
- `CMakeLists.txt`：`ZLPE_WIN_RESOURCES` + `add_executable` + `set_source_files_properties`
  （`/I <abs>/resources`）+ `target_compile_definitions(... ZLPE_HAS_EXE_ICON=1)`。
- `run_tests.sh`：mainwin 清单补 `src/ui/AppInfo.cpp`；★ 新增 `defines_for()` 钩子 ★ ——
  自检走自己的 `cl` 命令行、不经过构建系统，`ZLPE_HAS_EXE_ICON` 必须手工补。
  （不补的后果：`hasExeIcon()` 永远假 → 一条永远红的断言。）
- `tests/mainwin_test.cpp`：新增 `[8] 应用身份：显示名与图标`；原 `windowTitle()`
  断言从写死 `"ZlPhotoEdit"` 改成 `appinfo::titleSuffix()`（**断言一致性而非期望值**，
  否则改一次中文名要改一次测试，然后被人删掉）。

## ★ 本轮踩的四个坑（都值得记）

1. **`mainwin` 的 QSettings 隔离会污染身份断言**。`redirectSettingsToTempDir()`
   把 `applicationName` 改成了 `"MainWindowAssemblyTest"`，之后
   `QCoreApplication` 上挂的就不是真实程序的身份了 → 硬写 `checkStr(applicationName(), "ZlPhotoEdit")`
   得到**一条永远红的断言**，而它最可能的结局是有人"把测试的名字改回程序名"，
   **那才是真的把隔离破坏掉**。改法：按 `organizationName() == "ZlStudio"` 分支，
   未重定向才直接断真值，否则退到"源头"（AppInfo 常量）+ **源码对账**。
2. **源码对账要用正则/行过滤，别用"找第一对引号"**。`kApplicationName` 在
   `main.cpp` 的**注释里也出现**（就在定义上方），"找第一个 kApplicationName 再往右找
   第一个引号"会一路走到上一条定义 `kOrganizationName = "ZlStudio"` →
   断言报"期望 ZlPhotoEdit，实际 ZlStudio"。改成**逐行、跳过 `//`/`*` 开头的行**。
3. **图标覆盖率不能当判据**。logo 是"圆角方底 + 相机"，方底几乎铺满 viewBox，
   16px 覆盖率天然 **0.98** → "覆盖率 < 0.9"这种断言是在用另一张图的设计约束这张图。
   改成数 **32px 的不同颜色数**（实测 143）—— 抓的是"不是一整块纯色、细节真的画上了"。
4. **Python 在 Git Bash 里不认 `/tmp`**。`open('/tmp/x.md')` 报 `FileNotFoundError`，
   而 `ls /tmp/x.md` 明明在。改成先 `cp /tmp/x.md .buildlog/` 再用相对路径。
   ★ 另外 `python -c "...\`code\`..."` 里的反引号会被 bash 当命令替换**，写进文件的
   反引号全部消失（本轮实际发生：文档里 `kApplicationName` 等一串反引号被剥掉，
   靠 `grep -o` 复核才发现）→ **含反引号的文本改用 heredoc `<< 'PYEOF'`**。
