## ★ 本批核心：两套坐标系，参数名必须带空间后缀 ★

| 信号 | 空间 | 实现 |
| --- | --- | --- |
| `requestPan(delta)` | **控件坐标** | `CanvasView::panBy` |
| `requestZoom(factor, anchor)` | **控件坐标**（锚点 = 鼠标此刻的控件点） | `CanvasView::setZoomAt` |
| `requestZoomToRect(rect)` | **图像坐标** | `CanvasView::zoomToRect` |

三条踩到的坑：
1. `requestZoom` 第二参数原名 `imageAnchor` → 800% 缩放下锚点完全错。
   锚点**物理上只能是控件坐标**（"鼠标底下那个像素不动"）。→ 改名 `anchorWidget`。
2. `requestPan` 用图像坐标算 → `m_offset` 是控件量 → **怎么拖都不动**（高缩放尤甚）。
3. `requestZoomToRect` 是唯一图像坐标的。

**教训**：`delta` / `anchor` / `rect` 这样的名字**不够**。工程里只要有两种坐标系，
参数名必须带 `…Widget` / `…Image` 后缀 —— 否则下一个人一定传错，而且**不会报错**。

## 其余四条纪律（详见铁律第十四章）

- **平移增量 = 本次 − 上一次位置**（不是 − 按下点）。写成累计值 → 平方级加速冲出屏幕。
  且 `m_lastWidgetPos = e.widgetPos;` 的**赋值顺序在 emit 之前**。
- **框选阈值用控件坐标**（6px）；**退化（图像矩形 < 1×1）必须回落成单击**。
  退化时不回落 = `zoomToRect` 算出几千倍（除以近零宽度）；
  什么都不做 = "点了没反应，像卡死"。
- **Alt 反转用 XOR**：`zoomsIn(alt) = base != alt` —— 四种组合自动全覆盖，写 `if` 必漏一种。
- **共享步长 `kZoomStepFactor`** 放 `tools/ToolParams.h`（零 QtWidgets 依赖），
  工具 / 滚轮 / `zoomIn` 三处同源；顺手把滚轮里遗留的硬编码 `1.25` 也换掉了。
- **光标两态要靠画布补推**：状态在工具里，设置光标的只在 `refreshCursor()` →
  按下/松手后各补一次。属「装配顺序」族的变体：**状态改了但没人推**。
- **叠加层刻意不 gate 在 `view`**（`Q_UNUSED(view)`）→ 自检不建画布即可量像素（框必须空心）。

## ★★ 本批最重要的一条：计划里那句"不需要 engine 文件"是错的 ★★

架构规划 7.6 只讲了"用 `QTextEdit` 浮层做中文输入"，并写着"渲染直接走
`QPainter::drawText`，**不需要单独的 engine 文件**"。
实际落成时必须要有 `engine/Text`：文字工具处理的是
「一段文本 + 字体 + 对齐 + 行距 + 锚点 → 一堆像素」—— 这是一个
**有可被测度量**（包围盒 / 行距 / 对齐位移）的排版问题。
写在工具里 → 合成变成第四份实现，且自检只能"看图"（铁律第九章）。

## 七条纪律（详见铁律第十五章）

1. **内容归工具、浮层归画布**。`QTextEdit` 必须挂在画布上（定位到点击处），
   而 `tools/` 不许依赖 `ui/` → 浮层只能由 `CanvasView` 建。
   两端靠 `AbstractTool` 上的协议牵线，**画布不认识 `TextTool`**
   （写成 `static_cast<TextTool*>` 就把 `ui → 具体工具` 焊死了）。
2. **★ 锚点 = 文本块"首行顶部"**，不是 Photoshop 的首行基线。
   基线 = 顶部 + `ascent`，而 `ascent` 是字体属性 → 换字体文字整体上下跳，
   跨字体就没法顶部对齐。（实现里 `baseline = top + i*step + fm.ascent()`。）
3. **对齐只由框位置表达、框内一律左对齐**。每行各自按对齐算起点 = 施加两遍。
   ★ 核对位移量要用**排版宽度(advance)**，不能用墨迹宽度（差几个 side bearing → 假红）。
4. **★ 字距由字体携带**（`TextOptions::toFont` 把像素换算成百分比写进 `QFont`），
   引擎绝不再设一遍 —— "同一件事两处真相"，症状只是文字静静变宽。
5. **不自动换行 + 换行符先归一化**（`\r\n`/`\r` → `\n`；残留 `\r` 不可见却污染度量）。
   浮层也用 `NoWrap`，否则"浮层折行、落到图层不折"。
6. **蒙版像素值本身就是覆盖度**（底 0 + 白字 source-over → `out = 255*a`），
   不需要取 alpha 通道。但**"没有墨"必须单独判** —— 否则整段空白/字体缺失
   会走完整流程，压出一条"Ctrl+Z 什么也没发生"的空命令。
   `pad = 3` 的余量（抗锯齿 / 下划线 / 取整各占一条）。
7. **一次输入 = 一条 `DrawCommand::standalone()`**；浮层 5 条收口路径
   （Esc / 失焦 / Ctrl+Enter / 换工具 / 换文档）都走唯一 `closeTextEditor()`，
   先摘指针再 `hide()+deleteLater()` 防重入。

- `MainWindow` 侧也已就位：`m_docManager` + `m_doc`（当前文档缓存指针）+ `currentChanged`
  → 换 `m_doc` → 重建 `CommandStack` → **`applyDocumentToPanels(doc)`**（画布/状态栏/图层面板/
  工具管理器/历史面板重绑 + 动作可用状态统一刷新）。`setupCanvas` 注释明写"多标签化时这里
  换成 QTabWidget，其余代码不变"。
- **但 `openDocumentFromPath` 会关掉旧文档**（`closeDocument(oldIndex)`），所以现在是严格的单文档 UX；
  注释自己写着"多标签阶段要把这里改成'切换标签并返回'"。
- 耦合量：`MainWindowCommands.cpp` 有 **205 处** `m_document/m_doc`、148 处面板引用、
  74 处 `m_commandStack`。靠 `m_doc` 缓存指针可以让大部分引用不动，但**切标签时的重绑**
  是真正的风险面。

**最小改动方案：`打开为图层`（Layer from File）**
`MainWindow::pasteFromClipboard(bool asNewLayer)`（MainWindowCommands.cpp:1414）已经把
"建画布尺寸的 Layer → 算放置位置 → 宏合并一条撤销 → 设活动层"全做完了。抽出
`addImageAsNewLayer(const QImage&, const QString& name)` 即可复用，位置规则沿用现成的
②③（比画布小→居中，比画布大→贴左上角）。零架构改动。

**零改动方案（今天就能用）**：`copySelection()` 写的是**系统剪贴板**（自定义 mime + PNG 回退），
所以**开两个 ZlPhotoEdit 进程**：B 里 Ctrl+C → A 里 Ctrl+V 即为"粘贴为新图层"。
跨文档时 `isFromDocument()` 为假 → 自动走居中分支，行为正确。

## 踩过的坑（都已写进铁律第十六章）

1. ★ **带对话框的功能必须把"干活的那半"做成公开入口** ★
   `openAsLayer()` 第一件事是模态 `QFileDialog` —— 在无人环境里**永久挂死**。
   拆成 `openAsLayer()`（选文件）+ `importImageAsLayer(path, policy)`（干活）之后，
   截图工具能驱动它、自检能断言它，而且"不弹任何模态框"成了结构性保证：
   失败汇报统一走一个 lambda（`Ask` 弹框 / 其它只写状态栏）。
   **凡是带模态框的路径，在无人环境里都是挂死而不是报错。**
   与 `TextTool::placeText()` 绕过 `QTextEdit` 浮层是同一个套路。

2. ★ **截图工具拿撤销栈不能用 `findChild<CommandStack*>()`** ★
   拿到的是**第一个**子对象 = 已关闭的初始空文档留下的栈 → "撤销记录数"永远 0，
   三条断言集体误报"粒度不对"，而产品代码完全正常。
   根因：`MainWindow::setupDocumentManager()` 里**每个文档配一个 `CommandStack`**
   （命令内部持有 `Document*`），换文档时旧的 `deleteLater()`。
   当前文档的栈只有 `ToolManager` 手里有。

3. ★ **截图的位置本身就是断言的一部分** ★
   `_grown.png` 的 `grab()` 原本写在撤销**之后** → 截到的是"已经退回原画布"的状态，
   与上一张几乎一样。**数值断言全绿**，只有人眼看出两张图一样。
   凡是"先测后拍"的排列，都要问一句"拍的时候状态还对吗"。

4. ★ **"只宽不高"才区分得出"逐维取大"与"整体取导入图的尺寸"** ★
   第二张导入图做成宽 130%、高 80%：宽高都超时两种实现结果相同，断言白写。
   同时"只宽不高"让底图在新层上下露出来 —— 截图上一眼能看出"两张图叠着"。

5. ★ **新图层必须自己填满画布** ★
   `Document::addLayer()` 在图层大于画布时会静默 `setCanvasSizeInternal()` 扩画布，
   那条路径**不压任何命令** → 撤销回不去。
   且**断言必须用"比画布大"的图才测得出来**（小图上它只重排到左上角，画布不变）。

6. **放不下时的放置规则，粘贴与导入刻意不同**：粘贴用 `(0,0)`，导入一律居中
   （`centeredOffset` 会算出负数 → 两侧对称裁掉）。共用的是**建层**不是**放置**。
   这个差异容易被后人当 bug"修掉"，所以记进了铁律。

7. 宏的顺序：**先扩画布、后加图层**（几何快照含整份图层列表）；
   失败路径也必须 `endMacro()`（不配对 → 撤销栈永久停在"宏内"）。

## ★ 三个真 bug（全是"销毁 / 重绑顺序"上的）★

1. ★ **关标签段错误（use-after-free）** ★
   `removeDocumentTab()` 先删 `CommandStack`，而 `QUndoView`（`setStack` 内部存的是**裸
   `QUndoStack*`**）与状态栏还指着它 → 段错误（0 错 0 警）。
   → 新增 `aboutToRemoveTab(index)`，在**删任何东西之前的第一行**发出；
     `MainWindow::detachStackConsumers()` 负责解绑。析构路径**不经过信号**，直接
     `detachStackConsumers(nullptr)`。
2. ★ **关窗段错误（第二个）** ★
   `closeEvent` 已经把文档销毁了，却从没把面板里的 `Document*` 松开 → 后续析构继续用悬空指针。
   → `closeEvent` 里 `clearAllTabs()` 之后调 `activateTab(-1)`（= 空状态：文档相关菜单全变灰、
     面板收到 nullptr 指针）。**别再手写三行 `m_doc=nullptr`** —— 那是"漏一路就崩"的写法。
3. ★ **状态栏缩放比不跟页（只有看截图才发现）** ★
   切到 31.6% 的页，状态栏仍写着 99.9%。
   根因：`viewChanged` **只在变化时**发信号，换页时"当前 31.6%"不是一次变化 → 没人推它。
   → `applyDocumentToPanels` 里显式 `m_statusBar->setZoom(m_canvas->zoom())`。
   这是"**信号只传达变化、传不了现状**"的第三次现身。
   **教训：换对象之后，凡是"看板类"控件都要手动补推一次当前值。数值断言全绿，人眼一眼看出。**

## 两条规律（已写进铁律第十七章）

- **销毁一个对象之前，必须先让所有指着它的人松手。**（工程里的裸指针消费者：
  `QUndoView` / `StatusBarWidget` / `ToolManager`。）
- **信号只传达"变化"，传不了"现状"。** → 凡"换对象"，在看板上手动补推一次当前值。
- 附带：★ `QSignalBlocker` 只屏蔽该屏蔽的那一段 ★ —— `clearAllTabs()` 若整体包一层 blocker，
  会把 `aboutToRemoveTab` 一起吞掉（**静默**：不报错，只是解绑没发生 → 段错误回来）。

## 定位手法（值得复用）

段错误没有栈可读时：**在自检里临时加一个 `trace()`，把每条断言 flush 到 `stderr`（无缓冲）**，
崩溃前最后打印的那一行就是案发点（本次直接指到 `closeAct->trigger()` → `closeDocumentTab`）。
写完必须删掉 —— 它是临时探针，不是代码。

## 视觉证据

`shot.exe … multitab` → `.buildlog/multitab.png`（第 1 页，标题带 `*` 未保存标记）+
`multitab_switched.png`（切到第 2 页，标签选中态与页面内容都换了）。
自证：每页的标题 / 文档尺寸 / 缩放 / 撤销条数 / 可见画布数各不相同 —— 即"三件套确实每页一份"。
