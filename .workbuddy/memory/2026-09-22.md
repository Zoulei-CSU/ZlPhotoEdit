## 三、修掉 `run_tests.sh` 的 BOM

每次跑测试都在最上面刷一行
`./run_tests.sh: line 1: ﻿#!/usr/bin/env: No such file or directory`。

**根因**：`run_tests.sh` 带 UTF-8 BOM，shebang 实际是 `\xEF\xBB\xBF#!/usr/bin/env bash`
→ 内核不认、bash 把它当普通命令执行 → 报错。**`.sh` 和 `.pro` 一样不能有 BOM**
（要 BOM 的只有 `.cpp` / `.h` / `.md`）；`build_env.sh` 本来就没有，只有它带。

**修法**：`tail -c +4` 去掉前 3 字节（**不用 `sed -i`**），复核 BOM 没了 / CR=0 /
1312 行不变 / 首行与末尾都正常；`./run_tests.sh actions` 冒烟通过、报错行消失。

## 五、方案 B 侦察：**量完之后判定不做**，但挖到一个更划算的替代

### 5.1 新的探针 `.buildlog/probe_div.cpp`

把 `compositeLayer()` 的内层循环**逐字拷贝**成 6 个模板变体（`V0`~`V6`），
彼此只差"还原非预乘"那几行；每个变体都算 FNV 校验和与真实输出比对（逐位）。
编译命令与 `probe_perf.cpp` 同一套。

★ **必须先验证"逐字拷贝对得上真实函数"**，否则比值没意义：
`V0` = 29.7 ms，真实 = 35.3 ms（**0.84×**）。差价用 `V6`（V0 + 内联 mode 分派）
定位到 **mode 分派本身**（32.5 ms）—— 所以**只比"变体相对变体"的比值**，绝对值以真实函数为准。

### 5.2 方案 B 的实测天花板：**1.26×**

1920×1080 单层，`/O2`，3 次取最快：

| 变体 | 相对 V0 | 相对真实函数 | 逐位相同 |
| --- | --- | --- | --- |
| V0 逐字拷贝 | 1.00× | 0.84× | ✅ |
| **B″** 只表化 `/255`（2 KB） | 0.96× | **1.04×** | ✅ |
| **B′** 整表 `v/a`（512 KB） | **0.76×** | **约 1.26×** | ✅ |
| **B** `1.0/a` 倒数表（2 KB） | 0.79× | 约 1.22× | ❌ 口径风险 |
| 天花板（除法全换乘法，不可用） | 0.79× | 约 1.24× | — |

★ **B′ 已经摸到天花板** → 再往下压没有空间；**B″ 只有 4%**，可忽略。
★ 反直觉：**随机 alpha 也打不垮 512 KB 表**（同像素 3 次查表落在同一行，
逐像素换行仍有 1.21×）—— 原先"表被缓存击穿"的担心**不成立**（实测推翻，别照抄旧猜测）。
★ **B 与 B′ 在本次数据上恰好都逐位相同** —— 但这只是数据运气，不能当保证，
判决不依赖它。

### 5.3 判决：不做。三条理由

1. **天花板只有 1.26×，且只作用冷路径**。方案 A 已把热路径 431 ms 压到 0.25 ms，
   B 在热路径上**价值归零**；剩下的一次性操作（打开/拼合/合并）用户感知远低于每帧卡顿。
2. **代价不划算**：B′ 要 512 KB 常驻表 + 处理 `a==0` 的 256 个空位；
   B（2 KB）要改舍入，而它影响的正是"专抓 alpha 细微错误"的那批精确断言；
   同构代码在 `Adjust.cpp`，验证面还要扩到调整类。
3. ★ **收益与下面的快路径高度重叠，且被全面压过**：B′ 赚得最多的场景（全不透明照片）
   恰恰是快路径给 **7.8~9.4×** 的地方；B′ 的独占收益在半透明场景（1.26×），
   那里正是 alpha 边缘最敏感、最不该动内核的地方。

### 5.4 ★★ 副产品：**不透明上层直接覆盖**（收益远大于 B）★★

`qAlpha(src)==255 && layerAlpha==1.0` 时：`effAlpha` 精确为 1.0 →
`1.0-effAlpha` 精确为 0.0 → `mixR == br == sr`（Normal 模式），
反归一化再乘 255 取整**逐值还原** → **整条 source-over 退化成把 src 直接写进 dst**。

实测：全不透明上层 **35.9 → 4.6 ms（7.8×）**；
透明画布+照片 **35.5 → 3.8 ms（9.4×）**；两者**逐位相同（0/2 073 600 像素差异）**。
半透明/随机 alpha 场景无收益（不触发即不改行为）。

**代价：3 行、零查表、零口径变更**（不用改任何像素断言）。

★ **实现时必须加的门**：只有 `mode == Normal`（含按 Normal 处理的 `Dissolve`）
才成立 —— 其他混合模式的 `br != sr`，覆盖会算错。
**探针只跑了 Normal，这个门是从推导里来的**，别漏。

★ **穷举验证的三个诊断**（记在探针里，可重跑）：
`r/255.0*255.0` 往返 0/256 例外；`effAlpha==1` 时 `qRound(outA*255)==255` 0/256 例外；
`mixR` 路径 0 例外。

### 6.2 自检：`perf` 第 ⑪ 组（687 → 728 项，+41）

判据**必须两条同时成立**，缺一条都证明不了：

| 判据 | 抓什么 | 只有它会怎样 |
| --- | --- | --- |
| **逐位相同**（0 容差，结果与上层图逐位相等） | 快路径**算错** | 慢路径也算得对 → 说明不了快路径生效 |
| **命中计数吻合** | 门**写松 / 写紧** | 说明不了没写错 |

覆盖：11.1 候选集由 `blendChannel` 反推｜11.2 22 模式逐个（候选全命中且逐位等于上层；
非候选**一个像素都不许命中**）｜11.3 `opacity < 1` 门必须关｜11.4 混合层只数不透明那半
（逐像素判据，不是"整层否决"）｜11.5 经 `compositeLayersRegion` / `compositeLayers`
真实入口驱动｜11.6 区域路径只数重算的那块｜11.7 上层小于画布时的边界。

★★ **第一次跑就红了 15 条，两个原因都有价值** ★★

1. **候选集判据写错了**：只在一个采样点 `(base=0.3, blend=0.7)` 上比
   `blendChannel(m, b, v) == v` → "变亮"（`max`）与"线性光"（`b + 2v - 1`）
   在那一点上**碰巧恒等**，候选集从 2 个虚增到 8 个，6 条断言无辜变红。
   → **"在一点上取到同一个值" ≠ "恒等映射"**，要在一组采样点（7×7）上取交集。
   另外**分量模式（色相/饱和度/颜色/明度）要单独排除** —— 它们在 `compositeLayer`
   里根本不走 `blendChannel`（去 HSL 空间取分量），`blendChannel` 对它们只是
   default 分支退回 `blendNormal`。
2. **计数是按层累加的**：11.5 / 11.6 断言写成了 `total`，实际是 `total × 2`（两层各覆盖一遍）。
   → 这不是 bug，是"本次调用共有多少像素由快路径写出"；断言应写成 `× 层数`。
   这条本身成了植入 **W** 的靶子（把 `+=` 写成 `=` 就该红）。
