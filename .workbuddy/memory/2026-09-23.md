### 六条设计决策（详见 `MagicWandTool.h` 头注释 + 铁律第二十一章）
1. 判据**默认取合成图**（同吸管：所见即所得），可切「只取样当前图层」（同油漆桶）。★ Photoshop 默认相反 → 提示里写明。
2. **先羽化新蒙版**再 `applyMask()` —— 反序会把老选区边界也糊一遍。
3. **退化归一化**：减/交后 `bounds()` 为空 → `sel.clear()`，保住"无选区 = 快路径"。
4. `selectAt()` 必须 **public**（自检能逐条驱动四种运算，不必伪造鼠标事件）。
5. ★ **不做写前检查**（与油漆桶**有意不同**）：只改选区元数据，隐藏/锁定活动图层不该拦住。
6. `prepareCanvas()` 必须在写蒙版**之前**（否则 `applyMask()` 静默什么都不做）。

### ★ 踩到的坑：测试助手把"没有选区"和"全选"混为一谈
首跑 `magicwand`：**121 通过 / 2 失败**，两条都在 [5] 组「四种运算」。
⇒ 根因**不是工具**——同一组的 `check(!selection().isActive())` 是**绿的**。
是测试助手 `selValue()` 把"没有选区"折算成 `255`（= 全选），而 [5] 那一步恰好把选区**减到空**，
断言 `== 0` 于是假红。
修法：把 [5] 的"减去"改成**不退化**的版本（先并回 B，再减 A → 留下 B，逐点断 255/0 + 包围盒 = B）；
"减到空"这条边界交回 [6] 组（退化归一化）独管。
⇒ **记住**：想验"选区没了"，断 `isActive()`，**别断 `selValue() == 0`**。

### ★ 踩到的坑 ④：截图脚本自己指错了画布（**不是工具的错**）
- 现象：模式里 `selectAt()` **一直返回 false**、选区一动不动 —— 看起来像魔术棒坏了，
  可它的 125 项自检全绿、双构建也全绿。
- 根因 ①：**`findChild<CanvasView*>()` 返回的是"第一页"的画布**。
  多标签之后每页各有一个 `CanvasView`，而 `ToolManager` 持有的永远是**当前页**的文档 →
  我往第一页画场景、工具去选当前页 → 种子点落在工具那份画布之外（1200×800 vs 512×288）→
  工具**按规矩拒绝**。改成 `DocumentTabs::currentTab()->canvas` 立刻通过。
  ★ `fill` / `shape` / `handzoom` 等**旧模式还是 `findChild`**（都是多标签之前写的），将来再跑要先改。
- 根因 ②：**`tm->setActiveTool()` 放在了 `tm->loadAllOptions()` 之前** →
  后者把"上次使用的工具"恢复回来、压掉了设置 → 选项条上显示着**"文字"**的参数
  （而选区确实是魔术棒做出来的）。调换顺序即好。
- 教训：**"工具说自己失败"时，先核实脚本喂给它的到底是哪份文档、哪个画布**，别急着改工具。
  这与 MEMORY 里"装配顺序"那条静默失效同源。
