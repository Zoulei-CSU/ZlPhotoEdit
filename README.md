# ZlPhotoEdit

基于 Qt 5.15.16 的轻量级图片编辑器。纯 Qt 实现，零第三方依赖。

## 特性规划

- **图层系统**：多图层 + 22 种混合模式 + 不透明度 + 可见性控制 + 合并/拼合 + 拖拽排序
- **选区**：矩形 / 椭圆选区，支持添加、减去、交集，可羽化；**魔术棒**（按相似颜色一键成选区）
- **绘制工具**：画笔、橡皮、油漆桶、吸管、魔术棒、直线、矩形、椭圆、文字、抓手、缩放（共 15 个）
- **图像调整**：亮度、对比度、色相、饱和度、**曲线**、**色阶**、锐化、模糊、去色、反色
- **尺寸与画布**：图像大小（含自实现 bicubic 重采样）、画布大小（九宫格锚点 + 扩展色，缩小时智能适配）；两者都支持**像素 / 百分比**两种输入单位
- **几何变换**：图像旋转（90° 倍数 / 任意角度）、翻转、裁剪、缩放
- **剪贴板**：复制 / 剪切 / 粘贴选区，与系统剪贴板双向兼容
- **视图导航**：`QTransform` 视图矩阵、依托缩放、导航器面板、抓手/缩放工具、缩放级别下拉
- **视图辅助**：标尺（上方 / 左侧，单位可切 px / cm / mm / inch / pt）、参考线（从标尺拖出、可拖动 / 锁定 / 清除）、网格（**均为视图辅助，结构性不进导出图像** —— 参考线存在 `CanvasView` 里而不是 `Document` 里，所以"导出的图上有根蓝线"不可能发生）
- **文件**：新建、打开、**打开为图层**（把另一张图整幅加成本文档的一个新图层，见 [docs/实现要点详解.md](docs/实现要点详解.md)）、保存、另存为（含 PNG/JPEG/WebP 质量参数）、**另存为 ICO 图标**（自写编码器，`≤512` 硬上限，超限拒绝并说明原因）、未保存提示、EXIF 自动摆正
- **多标签页**：同时打开多个文档，**每页各有自己的文档 + 撤销栈 + 视图状态**（缩放/平移互不干扰），标签带 × 与未保存标记（`*`）；命令行多参数、拖入多个文件都开成多页；关窗口时逐页询问未保存内容
- **撤销重做**：基于 QUndoStack，历史面板可点击跳转
- **文件格式**：BMP / GIF / ICO（**自写编码器**，见 [docs/实现要点详解.md](docs/实现要点详解.md) 的「导出 ICO」）/ JPEG / PNG / SVG / TGA / TIFF / WBMP / WebP
- **平台适配**：高 DPI 缩放、内存降级与错误处理

| 魔术棒 | ✅ | **阶段七补入**（`tools/MagicWandTool`，`W`）：在画布上**点一下**，把"与落点颜色相近且相连"的一片变成选区；**一次点击 = 一条撤销记录**；容差 0~255（与油漆桶同一刻度）、连续 / 非连续、抗锯齿过渡带、四种运算（**新建 / 添加 / 减去 / 交集**，选项条上可切，也支持 `Shift` / `Alt` / `Shift+Alt` 临时覆盖）、羽化；★ **判据默认取合成图**（所见即所得，与**吸管**同口径），可切「只取样当前图层」（与**油漆桶**同口径）；★ 与油漆桶**有意不同**：它**不检查图层可写性** —— 它只改选区元数据、不写像素，隐藏/锁定活动图层不该拦住"先在别处框一块"；引擎**零新增**（复用油漆桶那条 `engine/Fill::floodFill()`，返回的是覆盖度蒙版，接到 `Selection::applyMask()` 上即可） |

| 抓手 | ✅ | **阶段六第三批**（`tools/HandTool`，`H`）：左键按住拖动即平移画布，光标**张开的手 ⇄ 握紧的手**两态。★ 位移一律是**控件坐标**（`m_offset` 本身就是"图像原点的控件坐标"，与位移同空间直接相加）—— 按图像坐标算的话 800% 缩放下"怎么拖都不动"；增量取自**上一次位置**而非按下位置（取按下位置会让拖动以平方级加速冲出屏幕）；原地抖动不发无意义的平移请求；**不碰文档、不压命令**，连撤销栈都不需要。与"按住空格临时平移"并存且不冲突（空格在事件派发阶段就被画布拦下，工具根本收不到） |

| 画布大小 | ✅ | `Ctrl+Alt+C`；**不重采样**，只改容器：九宫格锚点（自绘按钮，含 ↑↓←→↖↗↙↘ 与居中）、扩展色（前景/背景/白/透明，画笔可点选颜色）、相对模式（输入增量）；输入单位可选**像素 / 百分比**（四格组合：像素×绝对 / 像素×相对 / 百分比×绝对 / 百分比×相对）；左侧示意图实时画出新画布（实线）/ 原画布（虚线）/ 内容（蓝块）/ 被裁内容（红块）；缩小时按 `canvasResizeOffset()` 智能平移避免裁切，示意图与文档执行**共用同一函数** |
| 任意角度旋转 | ✅ | 「图像 → 图像旋转 → 任意角度...」；角度 0.1° 精度（滑块 ±180°，顺时针为正），**画布按包围盒自动扩大、内容一个像素都不裁**，四角用可选填充色（透明 / 背景色 / 白 / 黑）补齐；**预览走主画布**（降采样合成图 + 预览自带画布尺寸，视图自动适配）；输入 90° 倍数时仍走无损路径；0° 与 90° 倍数时填充色下拉置灰（那条路径没有需要填充的像素）；不进重采样内核选择（纯旋转时选哪个都一样，见 `RotateImageDialog.h`） |

| 图层面板 | ✅ | **阶段五的核心交付**（`ui/LayerPanel.*`）：行内自绘（缩略图 + 名字 + 混合模式·不透明度副标题 + 眼睛 + 锁）、多选、**拖拽排序**（`InternalMove`，落点 ⇄ `Document::moveLayer` 对拍）、双击/F2 重命名、底部 8 个功能按钮（新建 / 复制 / 删除 / 上移 / 下移 / 向下合并 / 合并可见 / 拼合）、顶部混合模式下拉（22 种）+ 不透明度滑块（拖动**只预览**、松手压**一条**命令）。**面板只读文档 + 只发信号**：一切改动由 `MainWindow` 包成 `LayerCommand` 压栈，撤销只有一条路径。★ 视图行序是**倒序**（文档索引 0 = 最底层，面板第 0 行 = 最顶层），全工程只允许 `layerpanel::rowToLayerIndex/layerIndexToRow` 两个函数做换算 |
| 标尺 / 参考线 | ✅ | **阶段七**（`engine/RulerMetrics.*` + `ui/RulerWidget.*`）：上方与左侧各一把标尺（厚 18px），单位 **px / cm / mm / inch / pt** 互切（物理单位按 DPI 换算，默认 96）；刻度步长随缩放自动选 **1/2/5×10ⁿ**，判据是**屏幕像素**（保证数字不叠在一起）；从尺子拖出参考线 —— ★ **参考线方向 == 尺子方向，位置取自垂直方向的位移**（顶部尺子拖出的是水平线，位置是 y）；松在尺子上 = 放弃、松到画布那边 = 落线（靠 Qt 的**隐式鼠标抓取**才能收到"已经移到画布上"的松手）；已落的线可在**画布上**拖动 / 拖出画布删除，命中容差是 **5 个控件像素**（图像坐标的容差会随缩放失真）；锁定后拖不动但照样画。★ **参考线存在 `CanvasView` 里（每页一份的视图状态），不在 `Document` 里** —— 于是"不进导出"是**结构性**保证而不是一个 `if`；两把标尺是**跨页共享**的，切页由 `activateTab()` 重指（不重指也"能显示"，只是刻度与图像对不上 —— 属于"看起来对、其实全错"）。菜单：「显示标尺 `Ctrl+Alt+R`」「标尺单位」「显示参考线 `Ctrl+;`」「锁定参考线 `Ctrl+Alt+;`」「清除参考线」 |
| 导出 ICO | ✅ | **阶段七**（`engine/IcoWriter.*` + `MainWindow::exportIcon()`）：另存为时选 `.ico` 即走**自写编码器**（不是 Qt 的 qico 插件）。★ **为什么要自己写** —— 实测 `QImageWriter(path,"ico")` 写 300×300 会**静默缩成 256×256**（写出的正是 256 尺寸的 BMP 条目，`errorString()` 还报成功），用户存 512 拿到 256 且零提示；另外 512 上限没处可拦、`qico.dll` 还是要单独部署的插件。★ 两种条目按尺寸自动选：**≤256 走 BMP**（40 字节 `BITMAPINFOHEADER` + 自下而上 32bpp BGRA + 1bpp AND 掩码）、**257~512 走 PNG 条目**（目录项宽高各只有 1 字节、`0` 表示 256，**结构上就装不下 256 以上**；此时宽高写 0，真尺寸以 PNG 头为准）。★ **上限 512 是产品定案**，超过就**拒绝**并弹窗说明（带实际尺寸、上限、以及"用「图像 → 图像大小」缩小"），**不默默缩小** —— 默默缩小的后果是"导出成功了"，用户回头才发现图被改小。判据是 `>` 不是 `>=`：**512×512 恰好放行**。★ 三个"写进去就错、肉眼看不出来"的坑都堵上了：`biHeight` 必须是 **2 × 高**（XOR 图 + AND 掩码合计）、AND 掩码**置 1 = 全透明**且最高位在最左（半透明**不置位**）、进文件前必须把**预乘**还原成非预乘（否则半透明边缘偏暗、不透明像素完全正常）。★ **分流点只有 `writeImage()` 一处** —— `saveDocument()`（Ctrl+S 到已有 `.ico`）与 `saveDocumentAs()` 都经过它，所以不会出现"另存为能存、Ctrl+S 又走回插件"。编码器自检 **317 项**（只链 Core+Gui，顺带守住"不依赖界面"）+ 主窗口装配 **51 项** + **8 条植入验证**；证明"真的走了自写分支"的判据是**打开一张 300×300 的 ico → 保存 → 读回来仍是 300×300**（弱判据"文件存出来了"抓不住 —— 插件也会写出一个合法 ico）。见 [docs/实现要点详解.md](docs/实现要点详解.md) |

## 快速开始

```bash
# 0) 环境：Qt 5.15.x（MSVC 构建）+ Visual Studio 2022；在 Git Bash 里先补好编译器环境
source build_env.sh

# 1) 构建 —— 方式一：qmake（与 Qt Creator 一致）
mkdir -p build && cd build && qmake ../ZlPhotoEdit.pro -spec win32-msvc "CONFIG+=release" && nmake -nologo

# 1) 构建 —— 方式二：CMake + Ninja
cmake -S . -B build_cmake -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build_cmake

# 2) 运行
./build/release/ZlPhotoEdit.exe          # qmake 产物
./build_cmake/bin/ZlPhotoEdit.exe        # CMake 产物
```
