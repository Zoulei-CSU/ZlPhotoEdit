## 0. 审计方法

从两个方向交叉对照找缺口：

1. **正向**：文档里已明确设计的功能，逐项列出
2. **反向**：以一个"能日常用起来"的图片编辑器应有的功能集为参照，逐项检查是否被覆盖

判定分三档：

| 标记 | 含义 |
| --- | --- |
| ✅ 已设计 | 有数据结构、算法或实现要点，可直接编码 |
| ⚠️ 提过名 | 只在一处出现过名字，无设计内容，等于没设计 |
| ❌ 空白 | 完全没有提及 |

## 1. 已是 ✅ 的部分

### 核心架构
- 五层单向依赖（`ui → tools → commands → core → engine`）

### 工具（15 个）
移动、画笔、橡皮、矩形选区、椭圆选区、**魔术棒**、裁剪、油漆桶、吸管、直线、矩形、椭圆、抓手、缩放、文字
（四个批次全部落地，阶段六已收口；**魔术棒**于阶段七补入 —— 工具箱里 15 个按钮全部在用、无预留）

### 图层
多图层 + 22 种混合模式 + 不透明度 + 可见性 + 锁定 + 图层增删改序

### 调整与滤镜
亮度、对比度、色相、饱和度、明度、锐化、高斯模糊、去色、反色、阈值、浮雕、怀旧、**曲线**

### 几何
图像大小（bicubic）、画布大小（智能适配）、图像旋转（90° 倍数 / 任意角度）、翻转、裁剪

### 文件与剪贴板
新建/打开/**打开为图层**/导出/另存为（带格式参数）、未保存提示、复制/剪切/粘贴（带蒙版）

**另存为 ICO**：自写编码器 `engine/IcoWriter.*`（`≤256` 走 BMP 条目、`257~512` 走 PNG 条目、
`>512` 拒绝），走 `MainWindow::writeImage()` 的单一分流点 —— Ctrl+S 与另存为共用。
★ 不用 `QImageWriter`：实测 qico 插件会把 300×300 **静默缩到 256×256**。
见 `架构规划.md` §3.12 / `实现铁律.md` 第十九章。

**屏幕截图**：「文件 → 屏幕截图」子菜单四项（立即截图 / 延迟 3 / 5 / 10 秒），
「立即截图」另挂**全局快捷键 `Ctrl+Alt+S`**（操作系统级热键 —— **最小化时照样能按**）。
平台相关代码全封在 `compat/ScreenCapture.*`（抓屏：设备像素 + dpr 归一 + 失败返回空图）
与 `compat/GlobalHotkey.*`（`RegisterHotKey` + `WM_HOTKEY` 走 `QAbstractNativeEventFilter`）。
★ 全局热键**只准备一个键是不够的**：这个组合键全系统只能有一个程序登记，占用它的
程序还会变（实测同一台机器上 `Ctrl+Alt+S` 几分钟内出现过"能登记"与"被占用"两种结果），
所以按**候选表**逐个试、第一个登记上的即为实际生效键，并**把真正生效的键写回菜单**
（菜单上写的必须就是能按的）；回落用的仍是窗口内快捷键兜底 + 状态栏说明原因。
延迟截图**先最小化自己、到点先抓后还原**；结果开成**一页内存文档**（不落盘），
与「文件 → 打开」共用 `createImagePage()` 这一份"图 → 一页"的实现。
见 `画布与文件操作设计.md` §6.9 / `实现铁律.md` 第二十二章。

### 多文档
多标签页（一页 = 一份 `Document` + 一份 `CommandStack` + 一块 `CanvasView`）、命令行多参数 / 拖入多文件开多页、逐页未保存确认

### 视图辅助
标尺（上方 / 左侧，单位 px / cm / mm / inch / pt）、参考线（从尺子拖出 / 画布上拖动删除 / 锁定 / 清除）、画布背景网格开关
（★ 参考线存**每页一份**的 `CanvasView`，不进 `Document` —— "不进导出"是**结构性**保证）

### 工程
`.pro` 配置、构建命令、Qt Creator 配置、MSVC 中文编码

### 3.1 视图导航 —— 这是最影响日常使用的缺口 ⭐️⭐️⭐️

现有文档只有 `zoomIn/zoomOut/zoomToFit/zoomToActualSize` 四个方法名。实际使用中这是**最高频的操作**，缺失会严重影响体验：

| 功能 | 说明 | 为什么重要 | 状态 |
| --- | --- | --- | --- |
| **导航器面板** | 缩略图 + 可视区域框，可拖动定位 | 大图编辑时唯一的"我在哪"参考 | ⬜ 待做（阶段七） |
| **抓手工具（H）** | 独立的平移工具 | 现在只有"按住空格"，但空格是临时修饰键，长按很累 | ✅ 已做（阶段六第三批） |
| **缩放工具（Z）** | 点按放大、Alt 点按缩小、拖框放大 | 精确缩放到某区域 | ✅ 已做（阶段六第三批，三种操作全做） |
| **缩放级别下拉** | 预设级别（25/50/100/200%…）快速切换 | 快速对齐到常用比例 | ✅ **已做**（状态栏是一个 `QComboBox`，可选项切换 —— 见 §3.2） |
| **Rulers 标尺** | 上方 / 左侧标尺，显示坐标 | 定位、对齐的基础设施 | ✅ **已做（阶段七）** |
| **参考线** | 从标尺拖出，可拖动可删除 | 对齐依赖它 | ✅ **已做（阶段七）**（拖动 / 删除 / 锁定 / 清除全有；移动与删除在**画布侧**做） |
| **网格** | 可开关的辅助网格，可设间距 | 排版对齐 | 🔄 只有画布背景网格的开关；**间距 / 对齐吸附待做** |
| **标尺单位** | px / cm / mm / inch / pt 切换 | 打印相关需求 | ✅ **已做（阶段七）**（物理单位按 DPI 换算，默认 96） |

> ★ 抓手 / 缩放的**实现难点全在“坐标空间”**（哪个量是控件坐标、哪个是图像坐标），
> 与前三批（改像素）完全不是一类问题。详见 `实现铁律.md` 第十四章。
>
> ★ 标尺 / 参考线的难点同样在坐标空间，而且还多一层**控件层级**：
> “画布左上角在本尺子坐标系里的位置”必须经**全局坐标**求
> （`mapFromGlobal(view->mapToGlobal(0,0))`）—— 标尺与画布是**兄弟**，
> 而 `mapTo(parent,…)` 的 `parent` 必须是**祖先**，传兄弟进去会**段错误**。
> 详见 `实现铁律.md` 第十八章。参考线存**每页一份**的 `CanvasView`（不进 `Document`），
> 于是“视图辅助不进导出”是**结构性**保证而不是一个 `if`。

**依赖关系**：标尺和参考线是**联动**的 —— 参考线从标尺拖出，两项必须一起做（已按这条落地）。网格相对独立。

### 3.4 视图变换的矩阵化 ⭐️⭐️

这是**架构级的隐患**。现有 `CanvasView` 只有 `zoom` + `offset` 两个标量：

```cpp
qreal  zoom() const;
void   setZoom(qreal factor, const QPoint& anchor);
void   setOffset(const QPoint&);
```

这只能表达**缩放 + 平移**。一旦要支持：

- **画布任意角度旋转查看**（不改变图像数据，只是显示旋转）
- **视图翻转**
- **多文档时的独立视图状态**

就必须升级成 `QTransform`：

```cpp
QTransform m_viewTransform;   // 图像坐标 → 控件坐标
```

**必须现在决定，因为改这个会牵动所有工具的坐标换算**（`widgetToImage` / `imageToWidget`）。虽然接口签名可以不变（内部改实现），但如果设计时按两个标量写，后面加旋转查看会到处返工。

**建议**：现在就用 `QTransform` 建模，`zoom()` / `offset()` 作为便捷访问器从矩阵中提取。

### 3.5 多文档 / 标签页 ⭐️⭐️

`MainWindow` 是单文档设计（持有一个 `Document*`）。现代编辑器都支持多开：

- `QTabWidget` 包多个 `CanvasView`
- 每个标签有自己的 `Document` + `QUndoStack` + 视图状态
- 标签的关闭确认（未保存提示）
- 多实例启动（命令行传多个文件）

**架构影响**：如果把 `Document*` 硬编码在 `MainWindow` 里，后面改多文档会大改。**建议现在就把"当前文档"抽象出来**，即使第一版只支持一个标签。

#### 3.5.1 多标签落地之前：已用「打开为图层」解决同一需求 ✅

用户提出的第一个真正跨文档的需求是：

> 从第二幅图片中选择一个区域，复制到第一幅图片上。

这句话里缺的**不是复制粘贴**（复制走系统剪贴板、粘贴为新图层早已实现），
而是**同时看到两张图**。所以先落地了改动最小、架构影响为零的那个方案：

**「文件 → 打开为图层…」**（✅ 已做，阶段七）。

把图 B 整幅变成一个图层后，“跨文档”问题退化成“跨图层”问题 ——
选区、反选、删除、移动这些图层内操作全部是现成的。
用户的操作变成：`打开为图层…` → 在新层上框选 → 反选 → 删除。

| 方案 | 代价 | 结论 |
| --- | --- | --- |
| 多标签页 | 要重构中央控件，影响面大 | ✅ **后续已落地**（阶段八，见上表与 `docs/架构规划.md` §3.8.3） |
| **「打开为图层」** | **零架构改动**，多用一步 | ✅ **已落地**（阶段七） |

多标签页与它不是替代关系而是**先后**关系 —— 落地之后“打开为图层”仍然有用
（它就是“把一张图导入成本文档的一个图层”这项能力本身）。
规格见 `docs/实现铁律.md` 第十六章（打开为图层）与第十七章（多标签）。

### 3.6 状态与偏好持久化 ⭐️

阶段七提了"最近文件 + 窗口状态持久化"，但没有设计：

- `QSettings` 的键名规范
- **工具参数持久化**：上次用的画笔大小/颜色，下次启动应保留
- **默认新建文档的尺寸与背景**（透明 / 白色 / 背景色）
- 撤销步数的用户可调
- 界面语言（如果做多语言）

### 3.7 错误处理与健壮性 ⭐️

文档基本没涉及：

| 场景 | 需要的行为 |
| --- | --- |
| 打开损坏的图片 | 给出可读错误，不崩溃 |
| 打开超大图（如 2 亿像素） | 内存预检 + 提示 + 降级（限制图层数量或提示风险） |
| 内存分配失败 | `QImage` 构造失败时的 `isNull()` 检查，优雅降级 |
| 磁盘满 / 无写权限 | 已在另存为里提到，但滤镜运算的临时内存不足没提 |
| 粘贴超大内容 | 剪贴板内容超过画布很多时的处理 |
| 撤销栈重建失败 | 压缩数据解压失败时不应崩溃 |

**一个具体的隐患**：`QUndoStack` 的整层快照方案，在内存紧张时 `qCompress` 也可能失败。需要有 `isNull()` 检查 + 放弃该步撤销记录（但仍执行操作）的降级路径。

### 3.8 元数据与色彩 ⭐️

- **EXIF 读取**：拍照方向（Orientation 标签）决定打开时是否自动旋转 —— **这个很实用**，很多手机照片带旋转标记
- **EXIF 保留**：导出时是否保留原始 EXIF（隐私考虑）
- **DPI 元数据**：读写图片的物理分辨率信息，影响打印
- **色彩空间**：文档明确不做 ICC 管理，但至少要**正确识别并保留** sRGB 标记，避免导出色偏

**EXIF 自动旋转**值得做，实现简单（读 `QImageReader::transformation()`，Qt 5.5+ 直接支持），收益明显。

### 3.9 打印与导出增强

- **打印**：`QtPrintSupport` 模块已确认可用（`Qt5PrintSupport.lib` 存在），但文档从未提及
- **导出 PDF**
- **导出动画 GIF**（`QImageWriter` 支持多帧写）
- **批量导出**：多个文件应用同一组操作

### 3.10 其他交互细节

| 功能 | 说明 |
| --- | --- |
| **画布右键菜单** | 上下文菜单（复制/粘贴/取消选择/适合窗口等），高频 |
| **画布边缘自动滚动** | 拖拽选区到画布边缘时自动平移 |
| **全屏模式** | `F11` 进入无干扰编辑 |
| **多显示器 / 高 DPI 适配** | Qt 5.15 需要设 `QT_ENABLE_HIGHDPI_SCALING`，否则高分屏下界面模糊 |
| **触摸板手势** | 双指缩放、双指平移 |
| **快捷键自定义** | 用户可改快捷键 |

**高 DPI 适配**在 Qt 5.15 上必须显式开启，否则在 4K 屏上整个界面都是模糊放大的。这是**启动代码里就要设置**的，属于容易漏但影响很直观的一项。

| **多文档抽象** | 架构级，硬编码单文档后面要大改 | ✅ **已做**（阶段一的 `DocumentManager` 抽象 + 阶段八的真正多标签页；改造时业务代码一行未改） |

| **状态栏交互**（缩放输入、颜色取样、进度条） | 长耗时操作的反馈缺失会让人以为卡死 | 🔄 坐标 / 取样 / 内存 / 消息 / 缩放下拉**已做**；**进度条未做**（见 §3.2） |

### P1 — 影响"好不好用"

| 功能 | 理由 | 处置 |
| --- | --- | --- |
| **标尺 + 参考线** | 对齐的基础设施，且两者联动 | ✅ 已做（阶段七）：`engine/RulerMetrics`（刻度纯函数，51 项自检）+ `ui/RulerWidget`（拖出）+ `CanvasView` 的参考线（拖动/删除/锁定）+ 网格宿主装配；主窗口 9 小节 57 项 + 6 条植入验证。★ 回出两个真 bug（同一个根因：`mapTo` 的 parent 必须是祖先，而标尺与画布是兄弟） |

| **错误处理与内存降级** | 健壮性 | 🔄 部分已有（尺寸类命令的内存预检、压缩快照） |

| **工具选项条架构** | 12 个工具都依赖它 | ✅ 已做 |
