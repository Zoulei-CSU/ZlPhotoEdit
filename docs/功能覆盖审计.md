## 0. 审计方法

从两个方向交叉对照找缺口：

1. **正向**：文档里已明确设计的功能，逐项列出
2. **反向**：以一个"能日常用起来"的图片编辑器应有的功能集为参照，逐项检查是否被覆盖

判定分三档：

| 标记 | 含义 |
| --- | --- |
| ✅ 已设计 | 有数据结构、算法或实现要点，可直接编码 |
| ⚠️ 提过名 | 只在一处出现过名字，无设计内容，等于没设计 |
| ❌ 空白 | 完全没有提及 |

## 3. ❌ 完全空白的重要功能

按重要性排序。

### 3.1 视图导航 —— 这是最影响日常使用的缺口 ⭐️⭐️⭐️

现有文档只有 `zoomIn/zoomOut/zoomToFit/zoomToActualSize` 四个方法名。实际使用中这是**最高频的操作**，缺失会严重影响体验：

| 功能 | 说明 | 为什么重要 | 状态 |
| --- | --- | --- | --- |
| **导航器面板** | 缩略图 + 可视区域框，可拖动定位 | 大图编辑时唯一的"我在哪"参考 | ⬜ 待做（阶段七） |
| **抓手工具（H）** | 独立的平移工具 | 现在只有"按住空格"，但空格是临时修饰键，长按很累 | ✅ 已做（阶段六第三批） |
| **缩放工具（Z）** | 点按放大、Alt 点按缩小、拖框放大 | 精确缩放到某区域 | ✅ 已做（阶段六第三批，三种操作全做） |
| **缩放级别下拉** | 预设级别（25/50/100/200%…）快速切换 | 快速对齐到常用比例 | 🔄 状态栏已显示比例（可单击输入待做） |
| **Rulers 标尺** | 上方 / 左侧标尺，显示坐标 | 定位、对齐的基础设施 | ✅ **已做（阶段七）** |
| **参考线** | 从标尺拖出，可拖动可删除 | 对齐依赖它 | ✅ **已做（阶段七）**（拖动 / 删除 / 锁定 / 清除全有；移动与删除在**画布侧**做） |
| **网格** | 可开关的辅助网格，可设间距 | 排版对齐 | 🔄 只有画布背景网格的开关；**间距 / 对齐吸附待做** |
| **标尺单位** | px / cm / mm / inch / pt 切换 | 打印相关需求 | ✅ **已做（阶段七）**（物理单位按 DPI 换算，默认 96） |

> ★ 抓手 / 缩放的**实现难点全在“坐标空间”**（哪个量是控件坐标、哪个是图像坐标），
> 与前三批（改像素）完全不是一类问题。详见 `实现铁律.md` 第十四章。
>
> ★ 标尺 / 参考线的难点同样在坐标空间，而且还多一层**控件层级**：
> “画布左上角在本尺子坐标系里的位置”必须经**全局坐标**求
> （`mapFromGlobal(view->mapToGlobal(0,0))`）—— 标尺与画布是**兄弟**，
> 而 `mapTo(parent,…)` 的 `parent` 必须是**祖先**，传兄弟进去会**段错误**。
> 详见 `实现铁律.md` 第十八章。参考线存**每页一份**的 `CanvasView`（不进 `Document`），
> 于是“视图辅助不进导出”是**结构性**保证而不是一个 `if`。

**依赖关系**：标尺和参考线是**联动**的 —— 参考线从标尺拖出，两项必须一起做（已按这条落地）。网格相对独立。

### 3.2 状态栏信息与交互 ⭐️⭐️

文档只在布局图里写了"状态栏: 坐标 | 图像尺寸 | 缩放比例 | 当前工具提示"，没有设计：

- **缩放比例的交互**：点击可输入具体百分比
- **坐标显示的坐标系**：图像坐标还是画布坐标？缩放后是否保持？

### 3.3 图层高级操作 ⭐️⭐️

原图层面板只有"新建/复制/删除/上下移动"。缺以下高频操作（**阶段五已收口，
逐项处置如下**）：

| 功能 | 说明 | 状态 |
| --- | --- | --- |
| **合并图层** | 向下合并、合并可见图层、拼合图像 | ✅ 三个全做（面板按钮 + 「合并可见图层 Ctrl+Shift+E」菜单动作）。★ 实现时踩到两个真 bug：`mergeLayerDown()` 把上下层取反、`mergeVisibleLayers()` 的插入位置算在删除之后 —— 见 `实现铁律.md` 第十一章 |
| **栅格化** | 文字图层/形状图层转普通像素图层 | ⬜ 本项目**没有文字/形状图层**（文字工具直接写像素层），因此无需栅格化 |

| **图层缩略图刷新** | 刷新时机与节流 | ✅ `QTimer` 节流 300ms。**是节流不是防抖**：写成 `restart()` 的话，连续画的时候计时器永远不到期，缩略图在停笔前一直不刷 |
| **图层拖拽排序** | 面板内拖动改变顺序 | ✅ `InternalMove` + `dropRowToTargetIndex()`；守门断言是"4 层 × 5 个落点**每一组都真的调一次 `Document::moveLayer`** 再对拍" |
| **图层多选** | 批量删除、批量改属性 | 🔄 多选与**批量删除 / 批量复制**已做（`ExtendedSelection` + `rowsToLayerIndices`）；批量改属性（一次改多层的混合模式/不透明度）未做 |
| **图层对齐/分布** | 相对画布或相对选区对齐 | ⬜ 未做，优先级低 |
| 不透明度 | （原表未列） | ✅ 滑块拖动**只预览**、松手压**一条**命令 —— 否则拖一次会往撤销栈里塞几十条 |
| 混合模式 | （原表未列） | ✅ 面板顶部下拉，16 种 |
| 可见性 / 锁定 | （原表未列） | ✅ 行内眼睛 / 锁两个热点，绘制与命中**共用同一组纯函数** |

**图层缩略图刷新**当初点出的坑（"画笔每画一笔都重算会很卡"）已经踩实并解决：
按 300ms 节流 + 在控制器侧重建行。断言方式是连打 20 次 `contentChanged`
后看缩略图渲染计数 —— 增量必须 ≤ 1。

> 原图层面板是没有独立类的（一堆 `QListWidget` 操作内联在
> `MainWindowActions.cpp` 里，那个文件已一千多行）。阶段五把它抽成
> `ui/LayerPanel.*`，并把"视图行序 ⇄ 文档索引""行内热点命中""拖拽落点"
> 三件最容易写错的事抽成**不依赖控件的纯函数**（`namespace layerpanel`），
> 使它们可以不起窗口直接断言。

### 3.4 视图变换的矩阵化 ⭐️⭐️

这是**架构级的隐患**。现有 `CanvasView` 只有 `zoom` + `offset` 两个标量：

```cpp
qreal  zoom() const;
void   setZoom(qreal factor, const QPoint& anchor);
void   setOffset(const QPoint&);
```

这只能表达**缩放 + 平移**。一旦要支持：

- **画布任意角度旋转查看**（不改变图像数据，只是显示旋转）
- **视图翻转**
- **多文档时的独立视图状态**

就必须升级成 `QTransform`：

```cpp
QTransform m_viewTransform;   // 图像坐标 → 控件坐标
```

**必须现在决定，因为改这个会牵动所有工具的坐标换算**（`widgetToImage` / `imageToWidget`）。虽然接口签名可以不变（内部改实现），但如果设计时按两个标量写，后面加旋转查看会到处返工。

**建议**：现在就用 `QTransform` 建模，`zoom()` / `offset()` 作为便捷访问器从矩阵中提取。

### 3.5 多文档 / 标签页 ⭐️⭐️

`MainWindow` 是单文档设计（持有一个 `Document*`）。现代编辑器都支持多开：

- `QTabWidget` 包多个 `CanvasView`
- 每个标签有自己的 `Document` + `QUndoStack` + 视图状态
- 标签的关闭确认（未保存提示）
- 多实例启动（命令行传多个文件）

**架构影响**：如果把 `Document*` 硬编码在 `MainWindow` 里，后面改多文档会大改。**建议现在就把"当前文档"抽象出来**，即使第一版只支持一个标签。

**当前状态（已全部回填，2026-09）**：

| 项 | 状态 |

#### 3.5.1 多标签落地之前：已用「打开为图层」解决同一需求 ✅

### 3.7 错误处理与健壮性 ⭐️

文档基本没涉及：

| 场景 | 需要的行为 |
| --- | --- |
| 打开损坏的图片 | 给出可读错误，不崩溃 |
| 打开超大图（如 2 亿像素） | 内存预检 + 提示 + 降级（限制图层数量或提示风险） |
| 内存分配失败 | `QImage` 构造失败时的 `isNull()` 检查，优雅降级 |
| 磁盘满 / 无写权限 | 已在另存为里提到，但滤镜运算的临时内存不足没提 |
| 粘贴超大内容 | 剪贴板内容超过画布很多时的处理 |
| 撤销栈重建失败 | 压缩数据解压失败时不应崩溃 |

**一个具体的隐患**：`QUndoStack` 的整层快照方案，在内存紧张时 `qCompress` 也可能失败。需要有 `isNull()` 检查 + 放弃该步撤销记录（但仍执行操作）的降级路径。

### 3.8 元数据与色彩 ⭐️

- **EXIF 读取**：拍照方向（Orientation 标签）决定打开时是否自动旋转 —— **这个很实用**，很多手机照片带旋转标记
- **EXIF 保留**：导出时是否保留原始 EXIF（隐私考虑）
- **DPI 元数据**：读写图片的物理分辨率信息，影响打印
- **色彩空间**：文档明确不做 ICC 管理，但至少要**正确识别并保留** sRGB 标记，避免导出色偏

**EXIF 自动旋转**值得做，实现简单（读 `QImageReader::transformation()`，Qt 5.5+ 直接支持），收益明显。

### 3.9 打印与导出增强

- **打印**：`QtPrintSupport` 模块已确认可用（`Qt5PrintSupport.lib` 存在），但文档从未提及
- **导出 PDF**
- **导出动画 GIF**（`QImageWriter` 支持多帧写）
- **批量导出**：多个文件应用同一组操作

### 3.10 其他交互细节

| 功能 | 说明 |
| --- | --- |
| **画布右键菜单** | 上下文菜单（复制/粘贴/取消选择/适合窗口等），高频 |

## 6. 需要你决定的三件事

1. **视图矩阵化要不要现在改？** 我建议改 —— 接口签名不变，只是内部实现从"两个标量"变成"一个 QTransform"，现在改成本很低。理由：一旦按标量写完所有工具的坐标换算，后面加"旋转查看画布"时每个工具都要返工。

2. **多文档要不要纳入第一版？** 即使只支持单标签，把"当前文档"抽象出来（如 `DocumentManager`）的成本很小，但省掉后面的大改。我建议**抽象但不实现多标签**。

1. **"把'当前文档'抽象出来，即使第一版只支持一个标签"** ——
   阶段一的 `DocumentManager` 与"所有面板都提供 `setDocument()`"这两条准备，
   让阶段八的改造**业务代码一行没改**（`m_doc` / `m_commandStack` /
   `m_canvas` 三个成员名不变，只是从"唯一"变成"当前页"）。
2. **"带模态框的路径在无人环境里是永久挂死"** —— 这条在多标签上又验证了一次：
   `document_tabs_test` 与 `mainwin_test` 都**刻意绕开**"关闭有未保存修改的页"
   （会弹确认框，离屏下没人点它）。能钉住的只有它的**判据**（标签上的 `*`，
   与模态框共用同一个 `needsSave`），其余靠人眼。

**这次改造回出了三个真 bug，全部属于"顺序"问题**（详见 `docs/架构规划.md` §3.8.3）：

- 关页时撤销栈先被销毁，而历史面板（`QUndoView` 内部模型存的是**裸**
  `QUndoStack*`）还指着它 → 换绑时对已释放对象 `disconnect` → **段错误**；
- `closeEvent` 逐页销毁文档却没让面板松手 → 面板攥着野指针走完剩下的析构；
- 切页后状态栏的缩放比不跟着换（`viewChanged` 只在**变化**时发）。

前两条修成了**结构保证**（`aboutToRemoveTab` 信号 + `activateTab(-1)`），
第三条是**看截图**看出来的，补断言时做了植入验证。
两条规律已写进 `docs/实现铁律.md` 第十七章：
**"信号只传达变化，传不了现状"**、**"销毁一个对象之前，先让所有指向它的人松手"**。
