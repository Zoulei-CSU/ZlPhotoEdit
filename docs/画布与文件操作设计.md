# 画布与文件操作设计

> 本文档是 `架构规划.md` 的补充设计，覆盖五组功能：
> **图像大小 / 画布大小 / 图像旋转 / 选区复制粘贴 / 文件另存为**。
> 这几项在原规划里只是零散提过名字，没有实际设计。

## 0. 先厘清三组容易混淆的概念

设计之前必须把语义分清，否则接口一定会设计错。

### 0.1 图像大小 vs 画布大小

| | 图像大小（Image Size） | 画布大小（Canvas Size） |
| --- | --- | --- |
| 改什么 | 像素被**缩放** | 像素**不变**，只是容器变大/变小 |
| 内容变形 | 会（除非等比且用比例链） | 不会 |
| 典型用途 | 输出到不同分辨率、压缩文件体积 | 给图像加边框留白、裁掉多余边缘 |
| 数据变化 | 每个图层的位图都重采样 | 每个图层的位图被平移 + 补边或被裁切 |

**两者都会改变所有图层（以及选区）的尺寸** —— 这是必须贯穿的设计约束。任何只改一层而不管其它的实现都是错的。

### 0.2 内容旋转 vs 图像旋转

| | 内容旋转 | 图像旋转（Image Rotation） |
| --- | --- | --- |
| 作用对象 | 单个图层的内容 | 整幅图（所有图层） |
| 画布尺寸 | 不变，超出部分被裁掉 | **跟着变**（90° 的整数倍互换宽高，任意角度按包围盒扩大） |
| 菜单位置 | 图层 → 变换 | 图像 → 图像旋转 |
| 典型用途 | 摆正某个元素 | 摆正整张照片 |

原规划里 `transform.cpp` 只有前者。后者要补。

### 0.3 裁剪 vs 画布缩小

裁剪（`CropTool`）是**在画布上交互式框选**，用户拖鼠标定矩形，松手应用。
画布大小是**在对话框里输入数字**。

两者的底层操作是同一个 —— "把画布改成某个矩形区域"。所以应该共用同一个 `resizeCanvas()` 实现，只是入口不同。`CropTool` 内部就是把用户拖出的矩形交给 `resizeCanvas()`。

## 1. Document 接口扩展

在 `Document` 里新增以下方法。注意**全部改为可撤销**：这些方法本身不直接改数据，而是产生 Command 压栈。

```cpp
class Document : public QObject {
    // ... 原有接口 ...

    // ── 尺寸 ──
    QSize   size() const;                              // 当前画布尺寸

    /// 图像大小：缩放所有图层位图
    /// @param newSize   目标尺寸
    /// @param mode      重采样方式（放大用 Fast，缩小用 Smooth）
    void    scaleImage(const QSize& newSize,
                       Qt::TransformationMode mode = Qt::SmoothTransformation);

    /// 画布大小：不缩放像素，只平移 + 裁切/补边
    /// @param newSize   目标画布尺寸
    /// @param anchor    锚点，决定原有内容贴到新画布的哪个位置
    /// @param fillColor 扩展区域的填充色（透明时传 Qt::transparent）
    void    resizeCanvas(const QSize& newSize,
                         Qt::Alignment anchor = Qt::AlignCenter,
                         const QColor& fillColor = Qt::transparent);

    // ── 旋转 ──
    /// 整幅图旋转 90 的整数倍（无损，走整数变换）
    void    rotateImage90(bool clockwise);
    void    rotateImage180();

    /// 整幅图任意角度旋转（画布按包围盒扩大，无裁剪）
    /// @param angleDeg  顺时针角度
    void    rotateImageArbitrary(qreal angleDeg);

    /// 整幅图水平/垂直翻转
    void    flipImage(bool horizontal);

    // ── 剪贴板 ──
    /// 复制：把当前选区（或整个活动图层）的内容拷到剪贴板
    /// @return 是否成功（选区为空且无图层时为 false）
    bool    copySelection() const;

    /// 剪切：复制后清空源区域（受选区约束）
    bool    cutSelection();

    /// 粘贴：把剪贴板内容作为新图层插入
    /// @param asNewLayer   true = 新建图层；false = 写入当前图层
    /// @return 粘贴产生的图层索引，失败返回 -1
    int     pasteAsNewLayer();
    int     pasteIntoCurrentLayer();

signals:
    // ... 原有信号 ...
    void sizeChanged(const QSize& newSize);   // 画布尺寸变化，画布需要重新计算适配
};
```

### 1.1 尺寸变化的统一入口

上面四个尺寸相关方法（`scaleImage` / `resizeCanvas` / 三个旋转）都有大量重复逻辑，抽象成一个内部公共函数：

```cpp
private:
    /// 尺寸类操作的统一实现
    /// @param transform 应用于"图像坐标系 → 新图像坐标系"的变换
    /// @param newSize   变换后的画布尺寸
    /// @param interpolate 是否重采样（resizeCanvas 为 false，scaleImage 为 true）
    void applyGeometryChange(const QTransform& transform,
                             const QSize& newSize,
                             bool interpolate,
                             const QColor& fillColor);
```

各方法的调用方式：

```cpp
void Document::scaleImage(const QSize& sz, Qt::TransformationMode mode)
{
    // 纯缩放，无平移
    QTransform t;
    t.scale(qreal(sz.width())  / width(),
            qreal(sz.height()) / height());
    applyGeometryChange(t, sz, /*interpolate=*/true, Qt::transparent);
}

void Document::resizeCanvas(const QSize& sz, Qt::Alignment anchor,
                            const QColor& fill)
{
    // 纯平移：把旧内容的左上角挪到新位置
    const QPoint offset = anchorOffset(size(), sz, anchor);
    QTransform t;
    t.translate(offset.x(), offset.y());
    applyGeometryChange(t, sz, /*interpolate=*/false, fill);
}

void Document::rotateImageArbitrary(qreal deg)
{
    // 先算旋转后的包围盒
    QTransform t;
    t.rotate(deg);
    const QRectF bounds = t.mapRect(QRectF(QPointF(0, 0), QSizeF(size())));
    t.translate(-bounds.left(), -bounds.top());   // 平移到原点
    applyGeometryChange(t, bounds.size().toSize(),
                        /*interpolate=*/true, Qt::transparent);
}
```

**好处**：三个功能的边界情况（图层、选区、动画帧、Command 构造）只写一遍。

### 1.2 锚点计算

```cpp
/// 根据对齐方式计算旧内容在新画布中的偏移
static QPoint anchorOffset(const QSize& oldSz, const QSize& newSz,
                           Qt::Alignment a)
{
    const int dx = (newSz.width()  - oldSz.width())  / 2;
    const int dy = (newSz.height() - oldSz.height()) / 2;

    int x = dx, y = dy;                            // 默认居中
    if (a & Qt::AlignLeft)   x = 0;
    if (a & Qt::AlignRight)  x = newSz.width()  - oldSz.width();
    if (a & Qt::AlignTop)    y = 0;
    if (a & Qt::AlignBottom) y = newSz.height() - oldSz.height();
    return { x, y };
}
```

用 `Qt::Alignment` 而不是自定义枚举的好处：可以直接对接 UI 上的九宫格按钮组。

### 1.3 智能适配偏移（画布缩小时）

`resizeCanvas` 在缩小时不用单纯的锚点计算，而是走智能适配 —— 在"内容完整可见"的前提下取最接近锚点位置的偏移。完整规则与实现见第 8.3 节。

锚点计算 `anchorOffset()` 是智能适配的**起点**，不是最终结果。

## 2. 尺寸类 Command

这个 Command 的共同点是：**记录所有图层的旧位图 + 选区旧蒙版**，undo 时整体恢复。

```cpp
/// 尺寸/旋转类操作。覆盖 scaleImage / resizeCanvas / rotate / flip 全部场景
class GeometryChangeCommand : public QUndoCommand {
public:
    GeometryChangeCommand(Document* doc,
                          const QSize& oldSize, const QSize& newSize,
                          const QList<QImage>& oldLayerImages,
                          const QList<QImage>& newLayerImages,
                          const QImage& oldMask, const QImage& newMask,
                          const QString& text);

    void undo() override;   // 写回 oldLayerImages / oldMask，恢复 oldSize
    void redo() override;   // 写回 newLayerImages / newMask，恢复 newSize

private:
    Document*         m_doc;
    QSize             m_oldSize, m_newSize;
    QList<QImage>   m_oldLayerImages, m_newLayerImages;
    QImage            m_oldMask, m_newMask;
};
```

### 2.1 内存问题与压缩策略

尺寸操作是**内存消耗最大的一类 Command** —— 它要存所有图层的前后两份位图。

举例：4 图层 × 4000×3000 × 4 字节 = 192MB，前后两份 = **384MB / 一步**。撤销栈 30 步的话，几个尺寸操作就能吃光内存。

必须做压缩。原始像素数据压缩率通常很高（大片同色区域、平滑渐变）：

```cpp
// 存储时压缩
QByteArray pack(const QImage& img) {
    QByteArray raw(reinterpret_cast<const char*>(img.constBits()),
                   int(img.sizeInBytes()));
    return qCompress(raw, 3);          // 级别 3：速度与压缩率的平衡点
}

// 取出时解压
QImage unpack(const QByteArray& data, const QSize& sz,
              QImage::Format fmt) {
    const QByteArray raw = qUncompress(data);
    QImage img(reinterpret_cast<const uchar*>(raw.constData()),
               sz.width(), sz.height(), fmt);
    return img.copy();   // 必须 copy —— raw 是局部变量，析构后指针失效
}
```

> **`copy()` 是必须的**。`QImage` 的构造函数是浅引用，不拷贝数据。`raw` 是局部变量，函数返回后内存被释放，那个 `QImage` 就成了悬空指针 —— 而且不会立刻崩溃，会在后续某个随机时刻出问题。这是极易踩的坑。

> **压缩级别选 3**：`qCompress` 内部是 zlib。级别 1 速度快但压缩率低，级别 9 反之。级别 3 对图像数据已经能拿到 80% 以上的压缩率，耗时也可接受（10MB 数据约 20ms）。级别 9 的额外收益很小但慢 3 倍。

**策略**：小于 8MB 的位图直接存原始数据（压缩反而增加解压开销且没那么省），超过阈值才压缩。

### 2.2 撤销栈调整

尺寸类操作占的内存远大于画笔操作。建议给 `QUndoStack` 设一个**总内存预算**而不是简单的步数上限：

```cpp
class CommandStack {
    static constexpr qint64 kMemoryBudget = 512 * 1024 * 1024;  // 512MB
    static constexpr int    kMaxSteps     = 50;
};
```

`QUndoStack` 本身只支持 `setUndoLimit()`（步数）。要按内存控制，需要给 `QUndoCommand` 加一个 `memoryCost()` 虚函数，在 push 之后检查累计值，超预算就手工清理最老的历史。

简化方案：**尺寸类操作单独限步数**（比如最多保留最近 3 次），其它操作沿用 50 步。实现上可以在 `GeometryChangeCommand` 的构造函数里检查栈中同类 Command 的数量。

## 3. 图像旋转的实现细节

### 3.1 90 的整数倍 —— 走无损路径

**关键**：90° 整数倍旋转**绝不能走任意角度那条路径**。虽然数学上等价，但插值会引入不必要的重采样误差。

```cpp
void Document::rotateImage90(bool clockwise)
{
    const QSize newSize(height(), width());       // 宽高互换
    QTransform t;
    t.rotate(clockwise ? 90 : -90);
    t.translate(clockwise ? -height() : 0, clockwise ? 0 : -width());
    applyGeometryChange(t, newSize, /*interpolate=*/false, Qt::transparent);
}
```

既然 `interpolate = false`，`applyGeometryChange` 内部就用 `QTransform` 的整数变换路径：

```cpp
if (!interpolate) {
    // Qt 的 transformed() 在变换为 90 的整数倍或镜像时会自动走快路径，
    // 不产生插值，结果与原图逐像素一致
    QImage out = img.transformed(t, Qt::FastTransformation);
}
```

> **验证方法**：写个单元测试 —— 准备一张所有像素值各不相同的图，旋转 90° 四次，结果应与原图 `==`（逐像素完全相同）。如果不能通过，说明走了插值路径。

### 3.2 任意角度 —— 画布按包围盒扩大

PS 里"图像 → 图像旋转 → 任意角度"的行为是：**画布自动扩大到能容纳旋转后的图像，多出来的角用背景色填充**（不是裁掉）。

```cpp
void Document::rotateImageArbitrary(qreal deg)
{
    QTransform t;
    t.rotate(deg);                                  // 顺时针为正

    // 算旋转后的包围盒
    const QRectF bounds = t.mapRect(QRectF(QPointF(0, 0), QSizeF(size())));

    // 平移到原点，避免出现负坐标
    t.translate(-bounds.left(), -bounds.top());

    const QSize newSize = bounds.size().toSize();

    // 大图必须先扩大累积器的尺寸，否则旋转后的角会被裁掉
    applyGeometryChange(t, newSize, /*interpolate=*/true, fillColor);
}
```

**`applyGeometryChange` 内部处理补边的正确做法**：

```cpp
QImage transformLayer(const QImage& src, const QTransform& t,
                      const QSize& newSize, const QColor& fill)
{
    // 直接给 transformed() 指定目标尺寸 + 变换模式，
    // Qt 会自动用透明（或指定色）填充未覆盖区域
    QImage out = src.transformed(t, Qt::SmoothTransformation);
    if (out.size() != newSize) {
        // 尺寸不符时手工补齐（transformed 有时会给出紧包围盒）
        QImage canvas(newSize, QImage::Format_ARGB32_Premultiplied);
        canvas.fill(fill);
        QPainter p(&canvas);
        p.setRenderHint(QPainter::SmoothPixmapTransform);
        p.drawImage(0, 0, out);
    }
    return out;
}
```

> **关于平滑插值的边缘**：`SmoothTransformation` 在图像边缘会产生半透明过渡像素（双线性采样到了图像外的"空"）。如果想要干净的边缘，需要在旋转前给源图**扩一圈边缘像素**（clamp 到边界值）再旋转，最后裁掉。

### 3.3 旋转的插值选择

| 角度 | 插值 | 原因 |
| --- | --- | --- |
| 90 / 180 / 270（整数倍） | `Qt::FastTransformation` | 纯整数像素重排，无插值损失 |
| 其它任意角度 | `Qt::SmoothTransformation` | 必然重采样，用平滑插值 |

**判断是否为 90 的整数倍**要用容差比较，不要用 `==`：

```cpp
const qreal r = std::fmod(std::abs(angleDeg), 90.0);
const bool isRightAngle = (r < 1e-6) || (90.0 - r < 1e-6);
```

浮点数的 `fmod(90.0, 90.0)` 可能返回 89.999999 或 0.000001，直接比较会误判，导致本该无损的旋转走了插值路径。

### 3.4 选区的同步处理

**选区蒙版必须跟着一起变换**。旋转后选区还在原来的位置就错了。

```cpp
// 在 applyGeometryChange 内部
if (!m_selection.isEmpty()) {
    QImage newMask = m_selection.mask().transformed(
        transform, Qt::FastTransformation);   // 蒙版不需要平滑插值
    // 尺寸不匹配时补齐为全 0（选区外）
    if (newMask.size() != newSize) {
        QImage padded(newSize, QImage::Format_Grayscale8);
        padded.fill(0);
        QPainter p(&padded);
        p.drawImage(0, 0, newMask);
        newMask = padded;
    }
    m_selection.setMask(newMask);
}
```

> 蒙版用 `FastTransformation` 而不是 `Smooth`。原因：选区的语义是"选中/未选中"的二值判断，平滑插值会在边界产生 1~254 的中间值，导致羽化效果被意外引入。

## 4. 复制 / 粘贴选区

### 4.1 剪贴板格式设计

**核心问题**：复制时要带上"选区蒙版"信息。如果只存一个 `QImage`，粘贴时无法知道哪些像素是选中的（透明像素和"未选中"无法区分）。

方案：用**自定义 MIME 类型**存储完整数据，同时提供标准 `image/png` 供外部程序使用。

```cpp
namespace ClipboardFormat {
    // 自定义格式，带选区蒙版的完整数据
    constexpr const char* kLayerData = "application/x-zlphotoedit-layer";

    // 标准格式，供其它程序（Word、QQ、PS 等）粘贴
    constexpr const char* kStandardImage = "image/png";
}
```

### 4.2 剪贴板数据结构

用 `QDataStream` 序列化：

```
struct ClipboardPayload {
    quint32 magic;        // 'ZLPE'，用于校验格式
    quint16 version;      // 版本号，便于后续扩展
    QImage  pixels;       // ARGB32，选区内容（选区外为透明）
    QImage  mask;         // Grayscale8，选区蒙版；无选区时为全 255
    QRect   sourceBounds; // 内容在原图中的位置，用于智能定位
};
```

```cpp
class ClipboardData {
public:
    static QMimeData* create(const QImage& pixels, const QImage& mask,
                             const QRect& sourceBounds);

    /// 从剪贴板读取。返回 false 表示剪贴板里没有本程序的数据
    static bool read(const QMimeData* data, ClipboardPayload& out);

    /// 能否从剪贴板读出"任意图像"（包括外部程序放的）
    static bool canReadAnyImage(const QMimeData* data);
};
```

**关键设计**：`sourceBounds` 记录了内容在原图中的位置。粘贴时用它判断：

- 如果粘贴目标的 `Document` **就是复制来源**（尺寸相同、路径相同）→ 按 `sourceBounds` 原位粘贴
- 否则 → 居中粘贴到画布

这是 PS 的行为，符合直觉：同一张图内复制粘贴应该原位落回，跨图粘贴则居中。

### 4.3 复制的实现

```cpp
bool Document::copySelection() const
{
    const Layer* layer = activeLayer();
    if (!layer) return false;

    QImage pixels;
    QRect  bounds;
    QImage mask;

    if (!selection().isEmpty()) {
        // 有选区：只复制选区内容
        bounds = selection().bounds();

        // 关键：用 masks 做 alpha 合成，把选区外挖成透明
        pixels = layer->image().copy(bounds).convertToFormat(QImage::Format_ARGB32);
        mask = selection().mask().copy(bounds);   // 与 pixels 同尺寸

        // 逐像素把蒙版值乘进 alpha 通道
        for (int y = 0; y < pixels.height(); ++y) {
            QRgb*      px  = reinterpret_cast<QRgb*>(pixels.scanLine(y));
            const uchar* m = mask.constScanLine(y);
            for (int x = 0; x < pixels.width(); ++x) {
                const int a = qAlpha(px[x]);
                px[x] = qRgba(qRed(px[x]), qGreen(px[x]), qBlue(px[x]),
                              a * m[x] / 255);      // 蒙版值参与 alpha
            }
        }
        pixels = pixels.convertToFormat(QImage::Format_ARGB32_Premultiplied);
    } else {
        // 无选区：复制整个图层
        bounds = QRect(QPoint(0, 0), size());
        pixels = layer->image();
        mask = QImage(size(), QImage::Format_Grayscale8);
        mask.fill(255);
    }

    QGuiApplication::clipboard()->setMimeData(
        ClipboardData::create(pixels, mask, bounds));
    return true;
}
```

> **注意蒙版参与 alpha 的那一步**。这是选区复制能正确工作的关键。如果直接用 `layer->image().copy(bounds)`，选区外的像素也会被复制进来，粘贴后就"漏"出来了。乘进 alpha 之后，选区外变成透明，粘贴时才不会带出多余内容。
>
> 羽化的选区边缘会得到 0~255 之间的 alpha，粘贴后自然形成柔边过渡 —— 这也是用灰度蒙版而非 QRegion 的一个直接收益。

### 4.4 粘贴的实现

```cpp
int Document::pasteAsNewLayer()
{
    ClipboardPayload payload;
    const QMimeData* data = QGuiApplication::clipboard()->mimeData();

    if (!ClipboardData::read(data, payload)) {
        // 剪贴板是外部程序的图片，降级处理
        if (!ClipboardData::canReadAnyImage(data)) return -1;

        QImage img = qvariant_cast<QImage>(data->imageData());
        if (img.isNull()) return -1;

        payload.pixels = img.convertToFormat(QImage::Format_ARGB32_Premultiplied);
        payload.mask = QImage(img.size(), QImage::Format_Grayscale8);
        payload.mask.fill(255);
        payload.sourceBounds = QRect(QPoint(0, 0), img.size());
    }

    // 决定粘贴位置
    QRect target = computePasteRect(payload);
    // 若超出画布，扩展画布容纳（或裁切，看用户偏好）

    // 创建图层
    Layer* layer = new Layer(QSize(size()), "粘贴的图层");
    QImage canvas(size(), QImage::Format_ARGB32_Premultiplied);
    canvas.fill(Qt::transparent);
    {
        QPainter p(&canvas);
        p.setCompositionMode(QPainter::CompositionMode_SourceOver);
        p.drawImage(target.topLeft(), payload.pixels);
    }
    layer->setImage(canvas);

    // 压栈
    auto* cmd = new LayerAddCommand(this, layer, activeLayerIndex() + 1,
                                    tr("粘贴"));
    commandStack()->push(cmd);

    return activeLayerIndex() + 1;
}
```

### 4.5 粘贴位置的计算

```cpp
QRect Document::computePasteRect(const ClipboardPayload& payload) const
{
    const QRect src = payload.sourceBounds;

    // 情况一：同一文档内复制粘贴 → 原位粘贴
    if (m_clipboardSourceDocument == this && size() == m_sizeAtCopyTime) {
        return src;
    }

    // 情况二：跨文档 / 尺寸已变 → 居中粘贴
    const QSize ps = payload.pixels.size();
    return QRect(QPoint((size().width()  - ps.width())  / 2,
                        (size().height() - ps.height()) / 2),
                 ps);

    // 情况三（可选）：目标超出画布时，自动扩大画布到刚好容纳
    //   QSize need = size().expandedTo(QRect(QPoint(0,0), ...).united(target).size());
    //   if (need != size()) resizeCanvas(need, Qt::AlignLeft | Qt::AlignTop);
}
```

> **情况三值得做**。用户从一个 4000×3000 的图里复制一块，粘贴到一张 800×600 的图里 —— 如果严格裁切，内容会丢一大半，体验很差。自动扩画布是更合理的行为。

### 4.6 粘贴的两种目标

| 方式 | 命令 | 行为 | 适用 |
| --- | --- | --- | --- |
| 粘贴为新图层 | `Ctrl+V` | 插入一个新图层，内容居中/原位 | 默认，安全，可单独调位置和混合模式 |
| 粘贴到当前图层 | `Ctrl+Shift+V` | 直接写入当前图层的对应位置 | 快速合成，无需管理图层 |

推荐**两者都提供**，默认前者。PS 的 `Ctrl+V` 其实是后者（粘贴到当前图层），但那是历史包袱，我们没必要照抄。

### 4.7 剪贴板与系统交互

**双向兼容**是必须的：

| 方向 | 要求 |
| --- | --- |
| 本程序 → 外部程序 | 必须提供 `image/png` 格式，否则 Word / QQ / 画图都粘不上 |
| 外部程序 → 本程序 | 要能读 `QImage`（Qt 会自动处理多种位图格式），并降级为"无蒙版"处理 |

实现上，`ClipboardData::create()` 要往 `QMimeData` 里**同时**塞自定义格式和 PNG：

```cpp
QMimeData* ClipboardData::create(const QImage& pixels, const QImage& mask,
                                 const QRect& bounds)
{
    auto* mime = new QMimeData;

    // 1. 自定义格式（完整数据）
    QByteArray blob;
    QDataStream out(&blob, QIODevice::WriteOnly);
    out.setVersion(QDataStream::Qt_5_15);
    out << quint32(0x5A4C5045)      // 'ZLPE'
        << quint16(1)
        << pixels << mask << bounds;
    mime->setData(ClipboardFormat::kLayerData, blob);

    // 2. 标准 PNG（供外部程序粘贴）
    //    注意：导出时用"已合成"的结果，不含透明以外的额外信息
    QByteArray png;
    QBuffer buf(&png);
    buf.open(QIODevice::WriteOnly);
    pixels.save(&buf, "PNG");
    mime->setData(ClipboardFormat::kStandardImage, png);

    return mime;
}
```

> **只提供 PNG，不要提供 BMP**。BMP 是未压缩的，一张 4000×3000 的图就是 48MB 直接进剪贴板，会拖慢整个系统。PNG 有压缩，体积小得多。

## 5. 另存为

### 5.1 Document 的文件状态管理

现在 `Document` 只有一个 `filePath()`，不够。需要区分"当前路径"和"是否有未保存改动"：

```cpp
class Document : public QObject {
public:
    QString filePath() const;              // 上次保存/打开的路径，空表示从未保存
    bool    isModified() const;            // 有未保存改动
    bool    hasEverBeenSaved() const;      // 是否曾经保存过（决定"保存"是否需要弹对话框）

    // 保存流程
    /// 保存到当前路径；路径为空则等价于 saveAs()
    bool save();
    /// 另存为。返回 false 表示用户取消或保存失败
    bool saveAs(const QString& path);

signals:
    void filePathChanged(const QString& newPath);
    void modifiedChanged(bool modified);
};
```

### 5.2 保存流程的状态机

```
save()
  │
  ├─ filePath() 为空 ─────→ 转 saveAs()（弹对话框选路径）
  │
  └─ filePath() 非空
        │
        ├─ 导出：合成所有图层 → QImage
        ├─ 按扩展名选格式与参数 → QImage::save()
        │     │
        │     ├─ 成功 → setModified(false)，更新窗口标题
        │     └─ 失败 → QMessageBox 报错，保持 modified 状态
        │
        └─ 成功


saveAs(path)
  │
  ├─ 用户在对话框中取消了 ──→ return false（不改变任何状态）
  │
  ├─ 路径与当前不同 ──→ 保存成功后 setFilePath(path)
  │
  ├─ 目标文件已存在 ──→ 覆盖确认（QFileDialog 默认已处理）
  │
  └─ 执行保存 → setModified(false)
```

**关键点**：

1. **另存为成功后要更新 `filePath`**。之后按 `Ctrl+S` 应该存到新路径，而不是旧路径。
2. **保存的是合成结果，不是图层数据**。本项目不做 PSD 读写（原规划明确排除），所以"保存"等于"导出一张扁平图片"。这一点要在 UI 上说清楚 —— 建议菜单里叫**"导出"**而不是"保存"，或者至少加个提示，否则用户会以为图层信息被保存了、关闭后能重新打开继续编辑。

> **这是个需要用户决策的产品问题**。三种处理方式：
>
> **(a) 保持"保存"语义，接受信息丢失** —— 简单，但用户容易误以为能继续编辑。
> **(b) 菜单写"导出图片"，另提供自定义工程格式** —— 需要额外设计一个 `.zlpe` 格式（用 `QDataStream` 存所有图层 + 混合模式 + 不透明度），存储成本不高，但增加了不少工作量。
> **(c) 折中：默认导出，但关闭时若检测到多图层就提示"图层信息不会被保存"** —— 成本最低的务实方案。
>
> 建议先用 (a) + (c) 的组合，把自定义格式作为后续扩展。**这块需要你确认一下倾向**，因为它影响菜单结构和用户预期。

### 5.3 格式与参数

不同扩展名要提供不同的保存参数：

| 格式 | 参数 | Qt 实现 |
| --- | --- | --- |
| PNG | 压缩级别 0-100（默认 50） | `QImageWriter::setCompression(level)` |
| JPEG | 质量 0-100（默认 90） | `QImageWriter::setQuality(quality)` |
| WEBP | 质量 0-100，可选无损 | `setQuality()` + `setOption("lossless", true)` |
| TIFF | 压缩方式（LZW / Deflate / 无） | `setCompression()` |
| BMP / GIF / ICO / TGA | 无参数 | 直接 `save()` |

**用 `QImageWriter` 而不是 `QImage::save()`** —— 前者能设置参数，后者只能用默认值：

```cpp
bool exportImage(const QImage& img, const QString& path, const ImageSaveOptions& opt)
{
    QImageWriter writer(path);
    if (!writer.canWrite()) return false;

    const QString fmt = writer.format().toLower();
    if (fmt == "png" || fmt == "tiff")
        writer.setCompression(opt.compression);
    if (fmt == "jpg" || fmt == "jpeg" || fmt == "webp")
        writer.setQuality(opt.quality);
    if (fmt == "webp" && opt.lossless)
        writer.setOption(QImageIOHandler::Option::CompressionRatio, 0);

    return writer.write(img);
}
```

### 5.4 另存为对话框

**不要直接用 `QFileDialog::getSaveFileName()`**，因为需要附加的参数控件（质量滑块等）。

标准 Qt 做法是用 `QFileDialog` 的非静态接口，通过 `setOption(DontUseNativeDialog)` 切换到 Qt 自己的对话框，然后用 `setLayout()` 塞进自定义控件：

```cpp
class ExportDialog : public QFileDialog {
    Q_OBJECT
public:
    explicit ExportDialog(const QString& defaultPath, QWidget* parent = nullptr);

    ImageSaveOptions options() const;

private slots:
    void onFilterChanged(const QString& filter);   // 切换格式时重建参数控件

private:
    QSlider*  m_qualitySlider;    // 1-100
    QLabel*   m_qualityLabel;
    QSlider*  m_compressSlider;   // 0-9（映射到 0-100）
    QCheckBox* m_losslessCheck;
    QWidget*  m_paramPanel;       // 参数区容器
};
```

> **原生对话框不支持自定义控件**。macOS 和 Windows 的原生保存对话框都是系统组件，无法塞东西进去。所以要用 `DontUseNativeDialog` —— 代价是失去系统原生外观，但换来功能。这是必须的取舍。

**格式过滤器的组织**：

```cpp
QStringList filters;
filters << "PNG 图像 (*.png)"
        << "JPEG 图像 (*.jpg *.jpeg)"
        << "WebP 图像 (*.webp)"
        << "TIFF 图像 (*.tif *.tiff)"
        << "BMP 图像 (*.bmp)"
        << "GIF 图像 (*.gif)"
        << "所有文件 (*)";
dialog.setNameFilters(filters);
dialog.setDefaultSuffix("png");     // 用户不输扩展名时自动补
```

> `setDefaultSuffix()` 很重要。用户输入 `myphoto` 而不带扩展名时，自动补成 `myphoto.png`，否则 `QImageWriter` 无法从路径推断格式，保存会失败。

### 5.5 文件名冲突与只读

| 情况 | 处理 |
| --- | --- |
| 目标文件已存在 | `QFileDialog` 的 `AcceptSave` 模式默认会弹覆盖确认，不用额外写 |
| 目标目录不存在 | 手动 `QDir().mkpath()` 创建，或报错 |
| 目标文件只读 | `QImageWriter::canWrite()` 会返回 false 或 `write()` 返回 false，捕获后提示 |
| 文件被其它程序占用 | Windows 下写入会失败，捕获 `writer.error()` 并给出可读的错误信息 |
| 磁盘空间不足 | `write()` 返回 false，错误码 `QImageWriter::DeviceError` |

统一处理成可读的提示：

```cpp
if (!exportImage(img, path, opt)) {
    QMessageBox::warning(this, tr("导出失败"),
        tr("无法写入文件：\n%1\n\n错误：%2")
            .arg(QDir::toNativeSeparators(path))
            .arg(writerErrorMessage(writer.error())));
    return false;
}
```

### 5.6 未保存提示

`MainWindow::closeEvent` 里的处理：

```cpp
void MainWindow::closeEvent(QCloseEvent* e)
{
    if (!m_doc->isModified()) { e->accept(); return; }

    const auto ret = QMessageBox::question(this, tr("未保存的更改"),
        tr("“%1”有未保存的更改，是否保存？")
            .arg(m_doc->displayName()),
        QMessageBox::Save | QMessageBox::Discard | QMessageBox::Cancel,
        QMessageBox::Save);

    switch (ret) {
    case QMessageBox::Save:
        // 保存失败（用户取消或写入出错）时阻止关闭
        if (!m_doc->save()) e->ignore();
        else                e->accept();
        break;
    case QMessageBox::Discard:
        e->accept();
        break;
    default:
        e->ignore();       // Cancel
        break;
    }
}
```

> **`save()` 返回 false 时必须 `e->ignore()`**。否则用户在"另存为"对话框上点了取消，窗口却仍然关闭，改动就丢了。这是常见的疏漏。

同样要处理的是**窗口标题的 `*` 标记**，让用户随时知道有未保存改动：

```cpp
void MainWindow::updateWindowTitle()
{
    const QString name = m_doc->filePath().isEmpty()
                       ? tr("未命名")
                       : QFileInfo(m_doc->filePath()).fileName();
    const QString mark = m_doc->isModified() ? " *" : "";
    setWindowTitle(QString("%1%2 — ZlPhotoEdit").arg(name, mark));
}
```

```

要点（全部已定案）：

1. **角度精度 0.1°**：滑块 -180.0°~180.0°（3600 档），数字框同精度，双向同步。
   整数度滑块只有 361 档，而"把扫描件摆正"这类最常见的用途恰恰需要 0.3°~1.5°
   的微调。滑块刻度取 0.1°，键盘微调也够用。
2. **顺时针为正**：与 Qt 的 `QTransform::rotate` 在 y 轴向下的坐标系下的视觉方向一致。
3. **预览走主画布**，不在对话框里画缩略图：用户看到的是整幅图在真实取景框里的样子，
   比一张小图信息量大得多。为此 `CanvasView` 的预览通道多了"预览自带画布尺寸"
   这一维（`setPreviewImage(image, canvasSize)`）—— 旋转会把画布撑大，不传新尺寸的话，
   撑到旧画布之外的那四个角会被取景框裁掉，而真实结果里那里是填充区。
   预览画布尺寸变化时视图自动"适合窗口"，否则用户看不到旋转出来的四角。
4. **预览源是降采样后的合成图**（不是活动图层）：旋转是整幅图的操作。
   降采样基准与调整类共用 1024 长边这一条（见 6.5）。
5. **扩展区域填充色**：透明 / 背景色 / 白色 / 黑色。
   **0° 与 90° 倍数时下拉置灰** —— 那条路径走整数坐标重排、画布与内容等大，
   没有需要填充的区域。置灰比"选了没反应"诚实得多。
6. **不提供重采样内核选择**：纯旋转时 `applyGeometry()` 没有前置缩放步骤
   （sx = sy = 1），插值由 QPainter 统一负责 —— 摆四项内核出来，用户无论选哪个
   结果都一样。给一个"选了不生效"的控件，比不给更糟。
7. **画布尺寸与 `rotatedBoundsSize()` 同源**：对话框"说"的数与 Document"做"的数
   必须来自同一个函数，杜绝"对话框说 5320×4120、确定后却是别的尺寸"。
8. **确定时走 `Document::rotateImageArbitrary()`**，而不是把 `apply()` 的结果塞回去：
   旋转要改**所有图层 + 画布尺寸**，还要能被一条 `GeometryChangeCommand` 撤销。
   好处是 Document 内部对 90° 倍数会走无损路径 —— 用户在对话框里输入 90，
   同样能得到逐像素相同的无损结果，不会被白糊一次。
9. **取消时连视图一起还原**：预览期间画布被撑大、视图被 `zoomToFit` 过，
   只清预览的话缩放会停在"适配大画布"那一档，用户一取消就会看到图突然变小。

**实现时揪出的两个真 bug**（记在 `docs/实现铁律.md` 第八章）：

- `contentOffset` 用的是"**未旋转**的内容中心"（`newCenter − oldCenter`），而
  `QTransform::rotate` 是围绕**原点**旋转的 —— 内容中心自己也会跟着转走。
  一般角度下内容会整体偏出画布、被裁掉一角，且四角的填充区一大一小。
  90° 倍数恰好掩盖了它（中心绕原点转 90° 后仍与画布中心对称），
  所以这条错误能一直潜伏到有任意角度旋转 UI 才现形。
- `applyGeometry()` 的插值分支把 `contentOffset` 与 `full.dx()/dy()` **加了两遍**
  （`full` 里已经含着那次平移）。而只有"任意角度旋转"会走到那个分支 ——
  90° 倍数走无损重排、纯平移走 `pureTranslate` 分支，所以同样一直没被发现。

**还有第三个 bug，但它跟前两个不是一类**：`MainWindowActions.cpp` 里
`imageMenu->addAction(m_actionRotateArbitrary)` 写了，而
`m_actionRotateArbitrary = new QAction(...)` **没写**。`QMenu::addAction(nullptr)`
是合法实参、静默什么都不做 —— 菜单项凭空消失，**编译 0 错 0 警、全部断言全绿**，
`ui_smoke_test` 也测不到（它根本不链接 `MainWindow`）。
真正抓到它的是**截图工具走真实菜单动作**（`findChild<QAction*>` 返回空）。

→ 已补 **`tests/action_check.py`**（`./run_tests.sh actions`）做静态对账，
守"动作四件套"：`new` → `setObjectName` → `connect` → `addAction`。
详见 [自检与验证.md](自检与验证.md)「编译器抓不到的错误：菜单动作对账」。
（`sliderAngle` / `spinAngle` / `comboFill` 三个 `objectName` 也是为此补的 ——
自动化靠它定位控件。）

### 6.5 曲线/色阶等调整对话框的共用预览机制

尺寸类操作和曲线一样，都面临"大图运算慢"的问题。可以复用曲线设计里那套**降采样预览 + 节流**方案：

- 拖动角度滑块时，在降采样副本上做旋转预览
- 松手/确定时全尺寸运算
- **始终在原图上重算**，不在上次预览结果上叠加（否则重采样误差会累积，图像越来越糊 —— 旋转比 LUT 变换更严重，因为它涉及双线性插值）

> 这点对旋转尤其重要。如果增量旋转，每次插值都会让图像更糊，转几次就废了。必须记录"进入对话框时的原图"作为基准。

### 6.6 尺寸输入的单位：像素 / 百分比 ✅ 已定案

**需求**：图像大小与画布大小两个对话框的宽度/高度输入框，除了像素，还要能按
**百分比**输入。

**定案**：

1. 两个对话框都加一个「单位」下拉框（像素 / 百分比），**同时作用于宽与高两个输入框**。
   不做"每个输入框各带一个单位下拉" —— 那样同一行里会出现两个单位控件，
   用户在"宽 50%、高 300 px"这种混合状态下几乎无法推理自己在做什么。
   对需要混合的场景，混合本身就说明该用像素单位。

2. 单位是**显示方式**，不是尺寸本身。切换单位时 `m_target` 一个像素都不动，
   与切换「相对」、勾选「长宽比」完全同一条规矩（见 `docs/实现铁律.md` 5.2）。

3. 百分比**始终相对原尺寸**（打开对话框那一刻的画布尺寸），与「相对」模式正交：

   | 单位 | 绝对（目标） | 相对（增量） |
   | --- | --- | --- |
   | 像素 | 新宽 = `n` px | 新宽 = 原宽 + `n` px |
   | 百分比 | 新宽 = 原宽 × `n`% | 新宽 = 原宽 × (100 + `n`)% |

   「相对 + 百分比」里的 `n = 50` 表示"在原有基础上加大五成"，与"绝对 150%"是
   同一个结果 —— 就像像素模式下"相对 + 400"与"绝对 4400"（原宽 4000）是同一个
   结果一样。两格只是同一目标值的两种记法，**不是两套算法**：实现上都是
   `percentToPixels(100 + n, 原尺寸)`。

4. 输入框的合法区间按 `(单位, 模式)` 计算，且**宽、高分别算**：

   - 百分比的像素目标被限制在 `[1, kMaxCanvasDimension]`，换算成百分比：
     上限 `(20000 × 100) / 原尺寸`（**向下取整**），下限
     `max(1%, 最接近 1 像素的那个整数百分比)`。
   - 4000×3000 的图上：宽的上限 500%、高的上限 666%（两个维度区间不同，
     共用一个区间必有一边永远拨不到顶）。
   - 上界向下取整的理由：4000 宽的图上 500% 恰好是 20000，501% 就越界。
     向上取整会让滑块"拨不到头"（拨到头反而被改写成更小的数）。
   - 相对模式再把区间整体平移 100（`[下限-100, 上限-100]`），于是 200 px 宽的
     画布下限是 -99%（目标至少 1%），**不会出现 0 像素的画布**。

5. 换算函数放在**引擎层**：`geometry::percentToPixels()` / `pixelsToPercent()`
   （`engine/Geometry.h`）。理由与 `canvasResizeOffset()` 相同 —— 一个算法只能有
   一处实现。取整一律**四舍五入（.5 远离零）**，不能截断：截断会让"缩到 50%
   再放回 100%"每次少一个像素，用户来回拉几下图就真的变小了。

6. 信息面板要跟着说清楚，不能只看"最长边"：

   - 图像大小：两轴比例一致（锁定长宽比时的常态）只写一个百分比；不一致时
     写成「宽 33.0%　高 25.0%」。否则会出现"输入框写 25%、面板写 33.0%"这种
     两个数各自都对、但看着像算错了的组合。
   - 画布大小：面板本来就报像素与面积百分比，不受单位影响（真值永远是像素）。

7. **不做**：物理单位（英寸 / 厘米 / 点 / 派卡）。那需要 DPI 元数据，而本工程
   把 DPI 只当作 EXIF 元数据处理（见 `docs/功能覆盖审计.md` 3.10 节），
   尺寸一律按像素计算。将来若做，`Unit` 枚举与 `inputRangeFor()` 的形态可以
   直接扩展。

**已验证**：`geometry_test` 第 12 组（换算的恒等 / 取整 / 单调 / 不动点扫描），
`ui_smoke_test` 的图像大小与画布大小两组（切换单位不改尺寸、上限分维、回写稳定、
相对+百分比的下限）。

### 6.7 裁剪工具（CropTool）✅ 已定案

**入口**：工具箱「裁剪」（快捷键 `C`）。与「图像 → 图像旋转」这类菜单命令不同，
裁剪是**在画布上框**，不在对话框里填数字。

**语义**：在画布上框出一个矩形，确认后把画布（连同所有图层与选区）变成那个矩形
—— 就是 `Document::crop(rect)`。与「画布大小」共用同一条底层路径（见 0.3 节）。

**为什么不做对话框**：矩形的位置与大小是**空间信息**，用数字表达要用户在脑子里做
两次坐标换算，还要来回看示意图。画布上直接拖才是所见即所得。所以裁剪的"参数"只剩
`CropOptions` 里的比例与网格两项，没有必须成批输入的东西 —— 这正是它与
图像大小 / 画布大小 / 任意角度旋转的分界：**那三个的操作数是标量，裁剪的操作数是矩形**。

**交互规格**（对齐 Photoshop）：

| 操作 | 行为 |
| --- | --- |
| 在框外按下并拖动 | 新建裁剪框（按下点固定为起始角） |
| 在框内按下并拖动 | 平移整个框（**整框钳制在画布内**，不会被推出画布） |
| 在 8 个手柄上按下并拖动 | 调整对应的边 / 角（对角固定） |
| 框外区域 | 半透明黑遮罩 —— 预览"这些像素将被丢掉" |
| 框内 | 按 `CropOptions::grid` 画构图辅助线（**只影响显示，不进结果**） |
| 双击框内 / `Enter` | 提交裁剪 |
| `Esc` | 复位到整幅画布（丢弃未确认的框） |
| 方向键 / `Shift` + 方向键 | 平移框 1 px / 10 px（与移动工具同一套手感） |
| 拖动时按住 `Shift` | 临时约束为正方形（覆盖比例预设） |
| 切换到别的工具 | 未确认的框**直接丢弃**（`commit()` 与 `SelectionTool` 同语义：没松手的框本来就不算数） |

**初始框**：工具激活后第一次需要画框时 —— 若有活动选区，用**选区包围盒**
（`Selection::bounds()`，用户的意图已经明确）；否则用**整幅画布**（PS 亦然）。
切走工具会丢弃未确认的框（见上表），所以切回来时**重新播种** ——
"框还在不在"完全由"这一轮工具会话有没有结束"决定，没有跨会话的隐藏状态。
画布尺寸一变（例如刚裁完一次）也重新播种：旧框已经不可能还在画布内了。

**比例约束**（`CropOptions::presetRatio`）：`Free` 不约束，其余在**新建与调整时**
保持宽高比，固定的是被拖动的**对角**（拖角）或**对边**（拖边）。实现要点：
**先把鼠标位置投影到坐标轴上**（取 `|dx|` 与 `|dy|·ratio` 里较大的那个方向为准），
再反算另一轴。直接对结果矩形做 `setHeight(width / ratio)` 会让框在水平/垂直之间
抖动 —— 因为"先改宽再改高"这个顺序本身就把用户的手势信息丢了。

**提交路径（★ 关键设计决定 ★）**：工具**不自己压命令**，而是发
`cropRequested(QRect)` 信号，由 `MainWindow` 执行：

```
快照 before = GeometryChangeCommand::captureState(doc)
doc->crop(rect)
commitGeometryChange(before, Kind::Crop, tr("裁剪"))
```

理由：几何类命令的内存预检（压缩后 > 256MB 就不记录撤销、并明确告知用户）
**只能有一个入口** —— 见 `MainWindow.h` 中 `commitGeometryChange()` 的注释。
工具自己 `new` 一个 `GeometryChangeCommand` 就等于开了第二个入口，而"漏掉预检"
的代价要到内存耗尽时才暴露。信号的方向也符合既有分层：`tools → ui` 只能靠信号
（`requestForegroundColor` / `requestZoom` 同此），反过来 include `ui/MainWindow.h`
是编译期就会报错的硬性越界。

**叠加层的屏幕尺寸恒定**：手柄与尺寸标签必须保持固定的**屏幕**像素尺寸（约定 9）。
但 `tools/` 层**不允许 include `ui/CanvasView.h`**（架构铁律 5），拿不到
`imageToWidget()`。解法：在 `paintOverlay()` 里先取 `painter.worldTransform()`
（此刻它就是画布刚设好的 `m_viewTransform`），再 `painter.resetTransform()`
把坐标系切到控件坐标，用 `t.map(...)` 自行映射后绘制。这个口径与画布自己完全一致，
不需要新增接口，也不破坏分层。

**`deleteOutside` 选项的处置**：选项条上**不再显示**「删除裁剪区域外的像素」勾选框。
本工程有一条贯穿全项目的隐含不变量：**图层位图尺寸恒等于画布尺寸**
（`crop` / `resizeCanvas` / `scaleImage` 都按画布尺寸重建位图；画笔落点、滤镜遍历、
选区蒙版全都按画布坐标索引图层像素）。「保留区域外内容」要求允许图层**大于**画布，
会同时波及画笔落点、滤镜遍历范围与合成缓存 —— 不是裁剪工具能单独承担的改动。
所以：**裁剪恒为破坏性**（区域外像素丢弃，可撤销），选项条该位置改成一行说明文字。
`CropOptions::deleteOutside` 字段与其 QSettings 键**保留不动**（避免用户配置漂移），
在头文件里标注为"允许图层大于画布"这一扩展点的入口。

**不做**：拉直（旋转裁剪框）、透视裁剪、框吸附到选区边缘/参考线、提交前把
"已裁掉的四角"再拖回来。最后一项 PS 支持（引擎里另存一份原图快照即可），
收益不抵内存 —— 裁剪本来就是低频操作，撤销栈里已有全图层快照。

**验证**：`crop_test`（手柄命中、新建/移动/调整的几何代数、比例约束、画布钳制、
退化框丢弃、提交矩形、复位）；`ui_smoke_test` 校验裁剪选项条。

### 6.8 菜单入口「图像 → 裁剪」✅ 已定案

工具箱的裁剪工具（6.7）是**鼠标框**，菜单项是**一次点击**。两者都在，语义不同：

| 入口 | 操作数 | 从哪里来 |
| --- | --- | --- |
| 工具箱「裁剪」/ `C` | 用户拖出的矩形 | 画布上交互 |
| 图像 → 裁剪 | **当前选区的包围盒** | 选区已经在对话里给过了，不必再框一次 |

**定案**：

1. 菜单项「裁剪」= 把画布裁到**当前活动选区的包围盒**（对齐 Photoshop 的
   `图像 > 裁剪`）。这是"选区先行、裁剪随后"这条工作流的收尾动作 ——
   用户已经用选框标出了要保留的部分，再让他拿裁剪工具重框一遍是重复劳动。

2. **没有选区时置灰**。不用内容包围盒兜底：那是「裁切到内容」的语义，
   把它塞进「裁剪」会让同一个菜单项在不同上下文下做两件不同的事。
   置灰状态在菜单**弹出时**（`QMenu::aboutToShow`）根据
   `Document::selection().isActive()` 刷新 —— 文档目前没有"选区已变化"信号，
   而菜单项只在弹出那一刻可见，所以"弹出时问一次"就够，
   比为此新增一个信号更省。

3. **矩形等于整幅画布时不压撤销栈**：状态栏提示
   「裁剪区域就是整幅画布，无需裁剪」—— `applyCropFromTool()` 在构造快照
   **之前**就挡掉，历史面板里不会多出一条"什么都没改"的记录。

   > ★ 实测补记（两处容易想反的地方）★
   > ① **「全选」动作本身会让菜单项置灰**，而不是"点击后弹提示"。
   >    因为在 `Selection` 的内部表示里，**"没有选区"就等价于"全选"**
   >    （蒙版填满 255，`m_active` 保持 false，好让绝大多数操作走
   >    "跳过蒙版运算"的快路径 —— 见 `Selection::prepareCanvas()` 注释）。
   >    于是 `isActive()` 仍是 false → 菜单项灰 → 上面那条提示
   >    **从菜单这条路走不到**。
   > ② 真正会走到这条提示的是**"拖满整幅画布"的选区**：它是活动选区
   >    （`isActive() == true`），但包围盒等于画布。

   > 另外记一句**入口可用性**：菜单项依赖选区（无选区即灰），而
   > 工具箱里的裁剪工具 `C` **任何时候都可用** —— 它不读选区，
   > 初始框由"选区包围盒 / 整幅画布"二选一播种。
   > 所以"裁剪灰着没法用"的正确自救方式是走工具，不是去凑一个选区。

4. 走的是与裁剪工具**完全相同**的提交路径（快照 → `Document::crop()` →
   `commitGeometryChange(Kind::Crop)`），历史面板里的显示文字也都是「裁剪」。

### 8.1 工程格式：先不做，但预留版本字段

**定案**：第一版**只导出扁平图片**，不做自定义 `.zlpe` 工程格式。

### 8.3 画布缩小：智能适配 ✅ 已定案

**定案**：画布缩到比内容小时，**自动平移内容以尽量保留**，而不是直接丢弃。

**定策依据**：这是比 PS 更友好的行为（PS 是直接裁掉）。用户把画布改小时，通常是想"裁掉某一边的空白"，而不是"砍掉一半图像"。自动平移能避免误伤。

**需要把"智能适配"定义清楚**，否则实现时会无从下手。规则如下：

```
输入：旧内容包围盒 contentBounds（非透明像素的范围）
      或 若内容全透明，则退化为 oldSize
      以及用户指定的新尺寸 newSize 与锚点 anchor

输出：内容在新画布中的偏移 offset

规则：
1. 若 newSize >= oldSize：走常规锚点逻辑（第 1.2 节 anchorOffset），不涉及智能适配
2. 若 newSize < oldSize（缩小）：
   a. 先按锚点算出常规偏移 offset0
   b. 检查内容是否被裁切：contentBounds 偏移后是否超出 newSize 范围
   c. 若未超出 → 采用 offset0
   d. 若超出 → 在"内容完整可见"的前提下，求出最接近 offset0 的偏移量
      （即把内容往画布内推，推到刚好容纳为止）
   e. 若内容本身比 newSize 还大（无论如何都装不下）→ 退化为按锚点居中裁切
```

具体实现：

```cpp
QPoint computeSmartOffset(const QSize& oldSize, const QSize& newSize,
                          Qt::Alignment anchor, const QRect& contentBounds)
{
    const QPoint base = anchorOffset(oldSize, newSize, anchor);
    if (newSize.width() >= oldSize.width() && newSize.height() >= oldSize.height())
        return base;                                  // 不缩小，无需适配

    // 内容在旧坐标系中的位置，加上基础偏移后就是它在新画布中的位置
    QRect placed = contentBounds.translated(base);

    // 若内容比新画布还大，装不下，只能按锚点裁切
    if (placed.width() > newSize.width() || placed.height() > newSize.height())
        return base;

    // 把内容往画布内推，推到刚好装下为止
    int dx = 0, dy = 0;
    if (placed.left()   < 0)              dx = -placed.left();
    if (placed.right()  >= newSize.width()) dx = newSize.width() - 1 - placed.right();
    if (placed.top()    < 0)              dy = -placed.top();
    if (placed.bottom() >= newSize.height()) dy = newSize.height() - 1 - placed.bottom();

    return base + QPoint(dx, dy);
}
```

**`contentBounds` 的计算**：需要扫描所有图层求非透明像素的并集包围盒。

```cpp
QRect Document::contentBounds() const
{
    QRect r;
    for (const Layer* l : m_layers) {
        if (!l->isVisible()) continue;
        r = r.united(nonTransparentBounds(l->image()));
    }
    return r.isNull() ? QRect(QPoint(0, 0), size()) : r;
}
```

> **性能注意**：`nonTransparentBounds` 要遍历像素，4000×3000 单线程约 20ms。可以走 `QImage::createAlphaMask()` 再用 `QRegion` 求边界，Qt 内部有优化，通常更快。计算一次即可，不要每次重绘都算 —— 建议在 `Document` 里做缓存，位图内容变化的脏矩形覆盖到边缘时才失效。

**对话框的反馈**：智能适配会平移内容，用户需要知道。在预览区画出来：

```
┌──────────────────────────────┐
│  ┌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┐          │  实线框 = 新画布
│  ╎ ┌───────────┐ ╎          │  虚线框 = 原画布范围
│  ╎ │  内容     │ ╎          │  实心块 = 实际内容包围盒
│  ╎ └───────────┘ ╎          │
│  └╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘          │
│                              │
│  ⓘ 内容已自动向内偏移 120px   │   ← 提示用户发生了位移
│    以避免被裁切               │
└──────────────────────────────┘
```

### 8.4 重采样：自写 Bicubic ✅ 已定案

**定案**：**实现自己的 bicubic（两次立方）重采样**，加入重采样方式选择。

Qt 只提供 `FastTransformation`（邻近插值，最近点）和 `SmoothTransformation`（双线性）。Bicubic 对照片的放大和二次缩小有可见的画质提升（更锐利、边缘更少锯齿），值得自己写。

#### 8.4.1 算法选择

Bicubic 卷积核的标准形式（Keys 三次卷积，a = -0.5）：

```
对距离 |x| ∈ [0, 2]：
    |x| <= 1:  W(x) = (a+2)|x|³ - (a+3)|x|² + 1
    1 < |x| < 2: W(x) = a|x|³ - 5a|x|² + 8a|x| - 4a
    其它:       W(x) = 0
```

取 `a = -0.5`（Catmull-Rom 参数），这是图像处理中的通用选择：锐度与振铃的平衡点。

> **注意振铃效应**：bicubic 在强边缘附近会产生轻微过冲（overshoot），表现为边缘旁的一条淡亮/暗线。`a = -0.5` 已经把振铃控制在可接受范围。如果实测发现太明显，可以改用 `a = -0.75`（PS 用的值，更锐但振铃更强）或 `a = -0.6`。**提供参数但默认 -0.5**。

#### 8.4.2 分离式实现（性能关键）

**绝不能做二维 4×4 卷积**。对每个输出像素做 16 次采样，4000×3000 → 2000×1500 就是 4800 万次采样，太慢。

正确做法是**分离成两次一维卷积**：

```
第一遍：水平方向，把宽度从 W0 缩放到 W1，高度保持 H0
第二遍：垂直方向，把高度从 H0 缩放到 H1，宽度保持 W1
```

复杂度从 `O(W1·H1·16)` 降到 `O(W0·H1·4 + W1·H1·4)`，提速约 2 倍多。这是所有高质量缩放的标准做法。

#### 8.4.3 权重预计算

**关键优化**：映射关系中，缩放比例是固定的（比如缩小到 1/2），所以**每个输出位置对应的权重是重复的**。

对水平方向：输出宽度 W1 时，只需预计算 `W1` 组权重，每组 4 个系数 + 一个源起始索引。垂直方向同理。这样避免在每个像素上重算三次多项式（那会非常昂贵，每个采样点要做 3 次乘方）。

```cpp
struct ResampleKernel {
    QList<int>    start;      // 每个输出位置的源起始索引
    QList<float>  weights;    // 每个输出位置的 4 个权重，扁平存储
    QList<int>    srcSize;    // 源尺寸
    QList<int>    dstSize;    // 目标尺寸
};

/// 预计算一维重采样表
ResampleKernel buildKernel(int srcSize, int dstSize, qreal a = -0.5);
```

权重计算：

```
对每个输出位置 i：
    center = (i + 0.5) * srcSize / dstSize - 0.5      // 源上的中心位置
    start  = floor(center) - 1                        // 4 个采样点从 center-1 开始
    对 j = 0..3：
        x = (start + j) - center                      // 相对距离
        w[j] = W(x)                                   // 三次卷积核
    归一化：sum = Σw[j];  w[j] /= sum                 // 必须归一化，否则亮度会变
```

> **归一化是必须的**。三次卷积核在非整数偏移处求和不为 1（比如缩小 2 倍时），不归一化会导致图像整体变亮或变暗。这是实现 bicubic 最容易漏的一步。

**边缘处理**：采样点超出源图像范围时，用**边缘像素 clamp**（而不是视为透明或黑）：

```cpp
static inline int clampIndex(int i, int n) {
    return i < 0 ? 0 : (i >= n ? n - 1 : i);
}
```

这样图像边缘不会出现暗边。

#### 8.4.4 实现骨架

```cpp
// engine/Resample.h / Resample.cpp

namespace Resample {

enum class Method {
    Nearest,      // 邻近，Qt::FastTransformation
    Bilinear,     // 双线性，Qt::SmoothTransformation
    Bicubic,      // 自实现，a = -0.5
    Lanczos       // 可选，进阶
};

/// 高质量重采样。内部自动决定走 Qt 还是走自实现
QImage scale(const QImage& src, const QSize& dstSize, Method m,
             qreal a = -0.5);

}
```

```cpp
QImage Resample::scale(const QImage& src, const QSize& dstSize, Method m, qreal a)
{
    if (src.size() == dstSize) return src;
    if (dstSize.isEmpty()) return QImage();

    // 邻近和双线性直接用 Qt 的实现，不要重造
    switch (m) {
    case Method::Nearest:
        return src.scaled(dstSize, Qt::IgnoreAspectRatio, Qt::FastTransformation);
    case Method::Bilinear:
        return src.scaled(dstSize, Qt::IgnoreAspectRatio, Qt::SmoothTransformation);
    default: break;
    }

    // Bicubic / Lanczos 走自实现
    QImage work = src.convertToFormat(QImage::Format_ARGB32_Premultiplied);

    // 第一遍：水平
    QImage tmp;
    if (dstSize.width() != work.width())
        tmp = resampleHorizontal(work, dstSize.width(), a);
    else
        tmp = work;

    // 第二遍：垂直
    QImage out;
    if (dstSize.height() != tmp.height())
        out = resampleVertical(tmp, dstSize.height(), a);
    else
        out = tmp;

    return out;
}
```

水平方向的实现骨架（垂直方向同理，只是遍历顺序与索引计算互换）：

```cpp
QImage resampleHorizontal(const QImage& src, int dstW, qreal a)
{
    const int srcW = src.width();
    const int h    = src.height();
    QImage dst(dstW, h, QImage::Format_ARGB32_Premultiplied);

    const ResampleKernel k = buildKernel(srcW, dstW, a);

    for (int y = 0; y < h; ++y) {
        const QRgb* srcLine = reinterpret_cast<const QRgb*>(src.constScanLine(y));
        QRgb*       dstLine = reinterpret_cast<QRgb*>(dst.scanLine(y));

        for (int x = 0; x < dstW; ++x) {
            const int    s = k.start[x];
            const float* w = &k.weights[x * 4];

            float r = 0, g = 0, b = 0, al = 0;
            for (int j = 0; j < 4; ++j) {
                const QRgb p = srcLine[clampIndex(s + j, srcW)];
                r  += qRed(p)   * w[j];
                g  += qGreen(p) * w[j];
                b  += qBlue(p)  * w[j];
                al += qAlpha(p) * w[j];
            }
            dstLine[x] = qRgba(int(r + 0.5f), int(g + 0.5f),
                               int(b + 0.5f), int(al + 0.5f));
        }
    }
    return dst;
}
```

> **关于预乘格式**：bicubic 在预乘 alpha 空间上做加权求和是**正确**的 —— 预乘格式的线性加权等价于正常的 alpha 合成，不会产生色偏。这和 LUT 查表的情况不同（那是非线性映射，必须转非预乘）。

#### 8.4.5 性能预算

以 4000×3000 → 2000×1500 为例：

| 阶段 | 计算量 | 单线程耗时估计 |
| --- | --- | --- |
| 构建水平 kernel | 2000 组 × 4 权重 | < 1ms |
| 水平遍 | 2000 × 3000 × 4 采样 | ~120ms |
| 构建垂直 kernel | 1500 组 | < 0.5ms |
| 垂直遍 | 2000 × 1500 × 4 采样 | ~60ms |
| **合计** | | **~180ms** |

半秒内完成，可以接受。但**在 UI 线程做会明显卡顿**，建议：

1. **显示等待光标** + 用 `QProgressDialog` 显示进度（分块报告）。
2. **或**用 `QtConcurrent::run` 放到后台线程，完成后用信号回主线程提交。注意 `QImage` 是值语义、可跨线程传递，无需额外同步。

由于水平遍和垂直遍之间有依赖，只有"每遍内部按行分块"能并行。可以进一步优化：**水平遍并行化** —— 每个线程处理不同的行区间（`blockingMap` 按行分块），因为每一行独立计算。

#### 8.4.6 对话框集成

`ImageSizeDialog` 的重采样下拉框扩展为四项：

```
重采样: [ 两次立方（最佳，适合照片）  ▾ ]
        ├ 邻近（硬边缘，适合像素画）
        ├ 双线性（快速，适合预览）
        ├ 两次立方（最佳，适合照片）      ← 默认
        └ 两次立方（更锐，PS 参数 a=-0.75）  ← 可选
```

默认选两次立方。**缩小图像时跳过邻近插值**（会产生严重锯齿），但如果检测到源图是硬边缘的像素画风格（可通过直方图判断颜色数很少），可以提示用户改用邻近。

> **与预览机制的配合**：对话框里拖动尺寸数字时，预览要用**双线性**（快），因为预览图本身已经降采样过；点确定时才用用户选的 bicubic 做全尺寸运算。否则拖动时每次都要 180ms，交互会卡死。

**实现位置**：放进 `engine/Resample.h / Resample.cpp`，作为独立模块。`Document::scaleImage()` 内部调用它。

```cpp
void Document::scaleImage(const QSize& newSize, Resample::Method method)
{
    QTransform t;
    t.scale(qreal(newSize.width())  / width(),
            qreal(newSize.height()) / height());
    applyGeometryChange(t, newSize, /*interpolate=*/false, Qt::transparent,
                        method);   // 重采样方式透传下去
}
```

> 注意 `applyGeometryChange` 的 `interpolate` 参数现在有了更细的语义 —— 它从 `bool`（是否重采样）变为 `Resample::Method`（用什么方式重采样）。`resizeCanvas` 传"不重采样"，`scaleImage` 传用户选的方法，旋转传 `Bilinear` 或 `Bicubic`（可配置）。
