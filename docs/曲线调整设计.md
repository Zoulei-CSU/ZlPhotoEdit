# 曲线调整功能设计

> 本文档是 `架构规划.md` 的补充设计，专门讨论曲线（Curves）调整功能。
> 曲线是图像调整类工具中表达力最强的单个功能，值得独立设计。

## 0. 为什么曲线值得单独设计

对比一下亮度/对比度的表达能力：

| 工具 | 可调参数 | 能表达的变换 |
| --- | --- | --- |
| 亮度 | 1 个标量 | 整体加减 —— 一条**平移**的直线 |
| 对比度 | 1 个标量 | 围绕中点的**斜率变化** —— 一条过中点的直线 |
| 色阶 | 4 个标量（黑白点 + 灰点） | 三个控制点的**分段线性**曲线 |
| **曲线** | **N 个任意控制点** | **任意单调或非单调映射** |

也就是说，亮度、对比度、色阶都是曲线的特例。曲线用一条贝塞尔或样条插值出来的曲线，把整个 [0,255] → [0,255] 的映射关系完全交给用户。

这带来的实际能力：

- **提亮阴影不炸高光**：把曲线左下段往上拎，右上段保持不变 —— 等效于"阴影"滑块。
- **压暗高光**：右段往下拉。
- **S 形对比曲线**：左下往下、右上往上 —— 这是最经典的"通透感"调法，比对比度滑块高级得多，因为它可以只加强中间调对比而不削顶。
- **反相 S 曲线**：降低对比、模拟"褪色胶片"。
- **压灰白 / 提黑位**：把左下端点上提，得到一种"雾感"；把右下端点下压，得到"褪色黑"（电影感）。
- **色调分离（Posterize 效果）**：曲线画成阶梯状。
- **单通道调色**：切到 R 通道把中间调往下拉、B 通道往上拉 —— 经典的"青橙调"。

这就是为什么它必须进第一梯队。

## 1. 核心数据结构

### 1.1 控制点与曲线

曲线的数学本质是一个 **单调分段三次插值**。核心数据只有"控制点列表"：

```cpp
// 一个控制点：输入值 → 输出值，均在 [0, 255]
struct CurvePoint {
    int x;   // 输入亮度，0 = 黑场，255 = 白场
    int y;   // 输出亮度
};
```

只用这一种数据类型，就能同时表达曲线、亮度对比度、色阶 —— 见第 1.4 节。

### 1.2 通道划分

PS 的曲线面板有 4 个通道可选。我们用枚举：

```cpp
enum class CurveChannel {
    RGB,  // 复合通道：同时作用于 R/G/B
    Red,
    Green,
    Blue
};

class CurvesModel {
public:
    // 每个通道一条曲线
    const QList<CurvePoint>& points(CurveChannel ch) const;
    void setPoints(CurveChannel ch, const QList<CurvePoint>& pts);
    void reset(CurveChannel ch);                     // 复位为 y = x 直线
    void resetAll();

    bool isIdentity(CurveChannel ch) const;          // 是否为恒等（无改动）

private:
    QList<CurvePoint> m_curves[4];   // 4 个通道
};
```

**为什么复合通道不合并进单通道？** 因为它们是叠乘关系而非相加：

```
final = curveBlue( curveGreen( curveRed( curveRGB(v) ) ) )
```

先走复合通道，再走各自的单通道。这样用户单独调 R 通道时，不影响已有复合曲线的效果。PS 就是这个语义，保持一致。

### 1.3 采样与 LUT 生成

曲线不参与逐像素数学运算，而是**预先烘焙成 256 项查找表**：

```cpp
// 把一个通道的曲线烘焙成 LUT
// out[i] 表示输入值 i 应映射到的输出值
std::array<quint8, 256> bakeLut(const QList<CurvePoint>& pts);
```

烘焙流程：

```
1. 若控制点少于 2 个，直接把两端点 (0,0) 和 (255,255) 补上
2. 按 x 升序排序控制点
3. 生成单调三次样条（见 1.5）或分段线性插值
4. 对 i = 0..255，求曲线在 x = i 处的 y 值
5. clamp 到 [0, 255] 并取整
```

烘焙一次是 256 次插值求值，微秒级。**每次参数变化烘焙一次，逐像素阶段只做查表。**

### 1.4 用控制点表达其它调整

这一节解释了为什么统一用"控制点列表"这个抽象是划算的。

| 调整 | 控制点表示 |
| --- | --- |
| 恒等 | `[(0,0), (255,255)]` |
| 亮度 +30 | `[(0,30), (255,255)]` |
| 对比度 ×1.5 | `[(0, -64), (128,128), (255, 320)]` 后 clamp |
| 色阶（黑点 20、白点 230、灰点 1.2） | `[(20,0), (128,128), (230,255)]` 按 gamma 修正中间点 |

好处是：**亮度和对比度对话框的实时预览，可以直接复用曲线的 LUT 烘焙流水线**，不必各写一套。方案上可以这样组织——

```
BrightnessContrastDialog 内部持有 CurvesModel
    → 拖动滑块时，更新控制点
    → 复用 bakeLut() 得到 LUT
    → 复用同一套 applyLut() 做预览
```

代价是亮度调整多了一次 256 项烘焙（可忽略），收益是少写一套映射代码，并且未来可以把三个对话框合并成一个"调整"面板。

> 不过要注意：**不要把亮度/对比度对话框强制改造成曲线界面**。滑块对普通用户更直观，曲线上手门槛高。两者并存，共用底层即可。

### 1.5 插值算法选择

有两条路线，建议**两条都实现，让用户可切**：

#### (a) 分段线性插值

控制点之间直接连直线。

- 优点：实现极简，**严格保单调**，结果可预测，用户拖动哪个点效果就变哪一段。
- 缺点：控制点少时曲线有折角，过渡不柔和。
- 适用：控制点多（≥5）时视觉上已经接近平滑；或者用户就想画出硬转折（如色调分离）。

#### (b) 单调三次样条（推荐默认）

即 Fritsch–Carlson 单调三次插值。它在普通三次 Hermite 样条上做了一步切线限制，**保证插值结果不产生过冲（overshoot）**。

为什么必须限制？普通 Catmull-Rom 样条在经过陡峭段时会产生回勾，表现为曲线在控制点附近"抖一下"—— 映射到图像上就是**暗部的细微反转，出现难看的色带和噪点**。这是所有曲线实现都必须处理的经典坑。

Fritsch–Carlson 的切线计算（设控制点 `(x_i, y_i)`，`Δ_i = (y_{i+1} - y_i) / (x_{i+1} - x_i)`）：

```
1. 初始切线（三点加权平均）：
     m_0 = Δ_0
     m_n = Δ_{n-1}
     m_i = (Δ_{i-1} + Δ_i) / 2    for 1 <= i <= n-1

2. 限制条件：若 Δ_i == 0，则置 m_i = m_{i+1} = 0
             否则收紧到圆盘内：
     a = m_i / Δ_i,  b = m_{i+1} / Δ_i
     s = a² + b²
     if (s > 9):
         t = 3 / sqrt(s)
         m_i   = t * a * Δ_i
         m_{i+1} = t * b * Δ_i
```

然后每段用标准三次 Hermite 基函数求值：

```
h = x_{i+1} - x_i
u = (x - x_i) / h
y = (2u³ - 3u² + 1) * y_i
  + (u³ - 2u² + u) * h * m_i
  + (-2u³ + 3u²) * y_{i+1}
  + (u³ - u²) * h * m_{i+1}
```

由于 x 是整数网格（0..255），烘焙时可以直接对**每个整数区间预计算四个 Hermite 系数**，然后逐点求值。这段代码不长，约 60 行。

**切线处理的两个细节**：

1. **端点**：第一个点和最后一个点的切线用单侧差分，不要用中心差分，否则曲线在端点会外翘。
2. **水平切线**：当相邻段斜率符号不同（峰/谷）时，切线必须置 0，否则会产生一个小的反向过冲。Fritsch–Carlson 的 `Δ_i == 0` 分支就是在处理这个。

## 2. 插值核心 —— 参考实现

放进 `engine/Curves.cpp`，纯函数，无 UI 依赖。

```cpp
namespace Curves {

// 控制点按 x 升序排列后，生成 256 项 LUT
std::array<quint8, 256> bakeLut(QList<CurvePoint> points, bool smooth);

// 内部：计算 Fritsch-Carlson 切线
static QList<double> computeTangents(const QList<CurvePoint>& pts);

// 内部：Hermite 求值
static double evalSegment(double x, double xi, double yi,
                          double xi1, double yi1, double mi, double mi1);

}
```

`bakeLut` 的骨架：

```cpp
std::array<quint8, 256> bakeLut(QList<CurvePoint> points, bool smooth)
{
    std::array<quint8, 256> lut{};

    // 1. 补齐端点
    if (points.isEmpty()) {
        points = { {0, 0}, {255, 255} };
    }
    if (points.first().x > 0)
        points.prepend({ 0, points.first().x == 0 ? points.first().y : 0 });
    if (points.last().x < 255)
        points.append({ 255, 255 });

    // 2. 排序
    std::sort(points.begin(), points.end(),
              [](const CurvePoint& a, const CurvePoint& b) { return a.x < b.x; });

    // 3. 恒等快路径 —— 最常见的"没调"场景，直接跳过所有计算
    if (points.size() == 2 && points[0].x == 0 && points[0].y == 0
                           && points[1].x == 255 && points[1].y == 255) {
        for (int i = 0; i < 256; ++i) lut[i] = quint8(i);
        return lut;
    }

    // 4. 求切线
    QList<double> m = smooth ? computeTangents(points)
                               : QList<double>(points.size(), 0.0);

    // 5. 逐点求值
    for (int v = 0; v < 256; ++v) {
        // 定位 v 落在哪一段
        int seg = 0;
        while (seg + 2 < points.size() && points[seg + 1].x <= v) ++seg;

        const auto& p0 = points[seg];
        const auto& p1 = points[seg + 1];

        double y;
        if (!smooth || p1.x == p0.x) {
            // 分段线性
            const double t = double(v - p0.x) / double(p1.x - p0.x);
            y = p0.y + (p1.y - p0.y) * t;
        } else {
            y = evalSegment(v, p0.x, p0.y, p1.x, p1.y, m[seg], m[seg + 1]);
        }

        lut[v] = quint8(qBound(0.0, std::round(y), 255.0));
    }
    return lut;
}
```

> **性能提示**：第 5 步里的 `while` 定位是 O(n) 的。控制点通常不超过 16 个，256 次循环总开销可忽略。如果非要优化，可以预先建一个 256 项的 `segmentIndex` 数组，或者用二分查找。

## 3. 应用 LUT —— 逐像素与并行化

拿到 LUT 之后，作用于图像的部分应该和 `Adjust.cpp` 里其它调整**共用同一套工具函数**。

```cpp
// engine/Lut.h —— 通用 LUT 应用工具
namespace Lut {

// 单通道 LUT 作用于 32 位图像（带 alpha，alpha 不变）
QImage applyToRgb(const QImage& src, const std::array<quint8,256>& lut);

// 三个独立 LUT 分别作用于 R/G/B（用于复合通道 + 单通道叠加的场景）
QImage applyToRgb(const QImage& src,
                  const std::array<quint8,256>& lutR,
                  const std::array<quint8,256>& lutG,
                  const std::array<quint8,256>& lutB);

// 带 alpha 蒙版（选区）的版本：蒙版为 0 的像素保持不变
QImage applyToRgbMasked(const QImage& src,
                        const std::array<quint8,256>& lutR,
                        const std::array<quint8,256>& lutG,
                        const std::array<quint8,256>& lutB,
                        const QImage& mask);

}
```

### 3.1 通道组合

当用户同时调了复合通道和单通道时，先烘焙出**每个色彩通道的最终 LUT**：

```cpp
// 把复合通道 LUT 和单通道 LUT 串成一条
std::array<quint8,256> composeLut(const std::array<quint8,256>& first,
                                  const std::array<quint8,256>& second)
{
    std::array<quint8,256> out{};
    for (int i = 0; i < 256; ++i)
        out[i] = second[ first[i] ];
    return out;
}

// 组装：RGB 复合 → R/G/B 单通道
auto lutR = composeLut(lutRGB, lutRed);
auto lutG = composeLut(lutRGB, lutGreen);
auto lutB = composeLut(lutRGB, lutBlue);

// 若三通道的复合结果相同（只有复合曲线改动），走单 LUT 快路径
if (lutR == lutG && lutG == lutB)
    result = Lut::applyToRgb(src, lutR);
else
    result = Lut::applyToRgb(src, lutR, lutG, lutB);
```

**这个快路径很重要**：绝大多数用户只调复合通道，此时三个 LUT 完全一致，走单 LUT 版本可以省掉两次查表和两次分支。同时 `applyToRgb` 单 LUT 版本可以放心地用 SIMD 友好的写法（连续内存顺序访问）。

### 3.2 逐像素实现

对 `Format_ARGB32_Premultiplied` 的图像：

```cpp
QImage applyToRgb(const QImage& src, const std::array<quint8,256>& lut)
{
    QImage dst = src;                       // 隐式共享，写时才拷贝
    const int h = dst.height();
    const int w = dst.width();

    for (int y = 0; y < h; ++y) {
        QRgb* line = reinterpret_cast<QRgb*>(dst.scanLine(y));
        for (int x = 0; x < w; ++x) {
            const QRgb p = line[x];
            // 注意顺序：必须先取出各分量，再一次性写回
            const int r = lut[qRed(p)];
            const int g = lut[qGreen(p)];
            const int b = lut[qBlue(p)];
            line[x] = qRgba(r, g, b, qAlpha(p));
        }
    }
    return dst;
}
```

> **预乘格式的陷阱**：`ARGB32_Premultiplied` 存储的是**已乘过 alpha 的值**。如果直接查表，等于在操作预乘后的数值，语义就错了 —— RGB 三个通道会被 alpha 缩放，导致半透明区域出现色偏。
>
> 两种处理方式：
>
> **方案 A（推荐）**：运算前转成 `Format_ARGB32`（非预乘），运算后再转回预乘。
> ```cpp
> QImage work = src.convertToFormat(QImage::Format_ARGB32);
> // ... 对 work 做 LUT 变换 ...
> return work.convertToFormat(QImage::Format_ARGB32_Premultiplied);
> ```
> 两次全图格式转换有开销，但换来正确的颜色语义。**对于调整类操作，正确性优先。**
>
> **方案 B**：直接在预乘数据上做，但要逐像素反预乘：
> ```cpp
> const int a = qAlpha(p);
> if (a == 0 || a == 255) { /* 直通或统一处理 */ }
> const int r = lut[qRed(p) * 255 / a];   // 反预乘后查表
> ...
> ```
> 除法开销大且需要处理 `a == 0` 边界，不建议。
>
> **结论**：在 `applyToRgb` 内部做格式转换，调用方无感知。同时可以在 `applyToRgb` 入口加个断言，确保输入是预期格式。

### 3.3 并行化

按行分块，每个线程处理不相交的行区间，写自己的行，无数据竞争：

```cpp
QImage applyToRgbParallel(const QImage& src, const std::array<quint8,256>& lut)
{
    QImage dst = src.convertToFormat(QImage::Format_ARGB32);
    const int h   = dst.height();
    const int rowsPerChunk = qMax(1, h / QThread::idealThreadCount());

    QList<int> starts;
    for (int y = 0; y < h; y += rowsPerChunk) starts.append(y);

    QtConcurrent::blockingMap(starts, [&](int y0) {
        const int y1 = qMin(y0 + rowsPerChunk, h);
        for (int y = y0; y < y1; ++y) {
            QRgb* line = reinterpret_cast<QRgb*>(dst.scanLine(y));
            for (int x = 0; x < dst.width(); ++x) {
                const QRgb p = line[x];
                line[x] = qRgba(lut[qRed(p)], lut[qGreen(p)],
                                lut[qBlue(p)], qAlpha(p));
            }
        }
    });

    return dst.convertToFormat(QImage::Format_ARGB32_Premultiplied);
}
```

> **阈值判断**：图像小于 1MP（约 1000×1000）时，线程创建与同步的开销可能超过收益。加个判断：`if (dst.size().width() * dst.height() < 1'000'000) 走单线程`。

### 4.2 坐标系约定

**必须明确一点：曲线控件的 y 轴是反的。**

图像坐标里 y 向下增长，但亮度语义上"上 = 亮"。所以控件内部需要转换：

```cpp
// 控件像素坐标 → 曲线值（0..255）
QPoint widgetToCurve(const QPoint& w) const {
    const int v = 255 - qRound(255.0 * (w.y() - m_plotRect.top())
                                     / m_plotRect.height());
    const int u = qRound(255.0 * (w.x() - m_plotRect.left())
                               / m_plotRect.width());
    return { qBound(0, u, 255), qBound(0, v, 255) };
}

// 曲线值 → 控件像素坐标
QPoint curveToWidget(int u, int v) const {
    return {
        m_plotRect.left() + qRound(m_plotRect.width()  * u / 255.0),
        m_plotRect.top()  + qRound(m_plotRect.height() * (255 - v) / 255.0)
    };
}
```

**所有内部状态都用曲线值（0..255）存储，只在绘制和命中检测时转换。** 这样曲线模型与控件尺寸彻底解耦，控件缩放时曲线不会变形。

### 4.4 交互行为

这是体验好坏的关键，列清楚：

| 操作 | 行为 |
| --- | --- |
| **左键点击空白处** | 在该位置**新增**一个控制点，并立即进入拖动状态 |
| **左键拖动控制点** | 移动该点。拖出控件边界时 clamp 到 0..255 |
| **拖动的横向约束** | 相邻控制点的 x 之间保持至少 1 的间隔 —— 不允许 x 交叉，否则插值会崩 |
| **右键点击控制点** | **删除**该点（端点不可删） |
| **双击曲线** | 在曲线当前位置新增点，并启用精细拖动 |
| **上下方向键** | 微调当前选中点的 y 值，步长 1（按住 Shift 步长 10） |
| **左右方向键** | 微调当前选中点的 x 值 |
| **Delete** | 删除选中的控制点（端点除外） |
| **光标显示** | 鼠标在绘图区内时，实时显示"输入 / 输出"数值框，跟随光标 |
| **按住拖动出界** | 不要 clamp 到控件边界就停住，允许 y 值超出 [0,255] 后在烘焙时 clamp。这样能画出"压到底"的曲线（输出恒为 0）。**但 UI 上仍然只显示 0..255 的绘图区**，超出部分表现为曲线贴在顶/底边 |

> **关于第 4 条**：如果不做横向约束，用户把两个点拖到同一个 x，相邻段长度变成 0，`Δ = (y1-y0)/(x1-x0)` 就是除零。必须在 `mouseMoveEvent` 里限制：
> ```cpp
> const int minX = (m_dragIndex > 0) ? m_points[m_dragIndex-1].x + 1 : 0;
> const int maxX = (m_dragIndex < m_points.size()-1)
>                  ? m_points[m_dragIndex+1].x - 1 : 255;
> ```

### 4.5 绘制细节

**背景网格**：4×4 的等分网格，浅灰色线，帮助用户定位中点和四分点。

**对角参考线**：从 (0,0) 到 (255,255) 的虚线，表示"恒等"位置。有了它用户能一眼看出自己把曲线往上还是往下拽了。

**背景直方图**：这是曲线面板里非常有用的辅助信息，**强烈建议做**。

做法：把当前图层（或选区范围内）的亮度直方图（256 个桶）作为半透明的灰色填充画在曲线底下，让用户看到像素都集中在哪个亮度区间。这样调曲线时就不是盲调 —— 直方图告诉用户"这张图的大部分像素在暗部"，于是自然就知道该去调左下段。

```cpp
void CurveEditor::drawHistogram(QPainter& p)
{
    if (m_histogram.isEmpty()) return;

    // 归一化：找最大值，用于缩放
    const int maxCount = *std::max_element(m_histogram.begin(), m_histogram.end());
    if (maxCount == 0) return;

    // 对数缩放，避免个别尖峰把其它柱压平
    QPainterPath path;
    path.moveTo(m_plotRect.bottomLeft());
    for (int i = 0; i < 256; ++i) {
        const double norm = std::log(1.0 + m_histogram[i]) / std::log(1.0 + maxCount);
        const int x = m_plotRect.left() + m_plotRect.width() * i / 255;
        const int y = m_plotRect.bottom() - int(m_plotRect.height() * norm);
        path.lineTo(x, y);
    }
    path.lineTo(m_plotRect.bottomRight());
    path.closeSubpath();

    p.fillPath(path, QColor(0, 0, 0, 24));
}
```

> **对数缩放是必要的**。照片的直方图往往在某几个亮度值上极度集中（比如大片天空、大面积白背景），线性缩放会让 99% 的柱子看起来都是一条平线。对数缩放能把暗部的细节也显示出来。也可以加个上限裁剪（比如忽略最高 0.5% 的桶），但一般对数就够了。
>
> **计算成本**：直方图要对整层遍历一次，4000×3000 是 1200 万像素，单线程约 30ms。可以接受，但**只在打开对话框时算一次**，不要每次拖动都重算。
>
> **存储成本**：`QList<int>` 256 项 = 1KB，完全不用担心。

**曲线绘制**：直接复用 `bakeLut` 的逻辑，但目的是取点而非烘焙：

```cpp
void CurveEditor::drawCurve(QPainter& p)
{
    // 复用与烘焙相同的插值逻辑，逐 x 求 y
    QPainterPath path;
    const auto lut = Curves::bakeLut(m_points, m_smooth);
    path.moveTo(curveToWidget(0, lut[0]));
    for (int i = 1; i < 256; ++i)
        path.lineTo(curveToWidget(i, lut[i]));

    QPen pen(m_curveColor, 1.5);
    pen.setCosmetic(true);          // 线宽不随缩放变化
    p.setRenderHint(QPainter::Antialiasing, true);
    p.drawPath(path);
}
```

> 直接复用 `bakeLut` 有个额外好处：**屏幕上看到的曲线，和实际作用于像素的映射，保证完全一致**。不存在"预览画的和实际用的不一样"的风险。

**控制点绘制**：5px 半径的圆，白色填充 + 深色描边。悬停时半径变 6px，拖动中填成曲线颜色。

**信息浮框**：跟随鼠标的小圆角矩形，显示 `输入: xxx  输出: yyy`。注意要处理靠近边界时的翻转，避免浮框被裁掉。

### 5.2 预览机制 —— 性能关键

**问题**：用户在曲线上拖动时，如果每次 `mouseMove` 都对全尺寸图像做一遍 LUT 变换，4000×3000 的图每帧需要几十毫秒，拖动会明显卡顿。

**方案：两级预览 + 节流。**

```
降采样预览（拖动过程中）
    图像缩到最长边 ≤ 1024
    → 约 100 万像素以内
    → LUT 变换 + 格式转换 < 5ms
    → 但显示器只有 ~60Hz，用 16ms 节流合并事件

全尺寸运算（松开鼠标 / 点确定）
    → 在真正的图层数据上做完整运算
    → 可能耗时几十到几百毫秒
    → 期间显示等待光标
```

具体实现：

```cpp
void CurvesDialog::onCurveChanged()
{
    if (!m_previewCheck->isChecked()) return;

    // 节流：16ms 内的重复调用直接丢弃
    if (m_throttle.isValid() && m_throttle.elapsed() < 16) return;
    m_throttle.restart();

    // 烘焙 LUT（256 次插值，微秒级）
    auto lutR = buildChannelLut(CurveChannel::Red);
    auto lutG = buildChannelLut(CurveChannel::Green);
    auto lutB = buildChannelLut(CurveChannel::Blue);

    // 在降采样副本上应用 —— 这一层已经很便宜了
    QImage preview = Lut::applyToRgb(m_previewBase, lutR, lutG, lutB);

    // 把预览结果贴回画布，用降采样副本的尺寸呈现
    emit previewImageReady(preview, m_previewScale);
}
```

**还原机制**：进入对话框时先备份原始图层 `m_original`。每次预览都在**原图**（而非上一次的预览结果）上重新运算 —— 这样避免误差累积。取消时直接 `m_original` 写回。

> 这里有个容易犯的错误：为了省事，在"上一次预览结果"上继续做变换。因为 LUT 本身是确定性的，一次变换的结果其实与增量变换等价（都是查表），但**格式转换的舍入误差会累积**，反复拖动若干次后颜色会偏移。所以必须在原图上重算。

**降采样副本的生成**：

```cpp
// 在构造函数里做一次
const QSize sz = m_original.size();
const int longest = qMax(sz.width(), sz.height());
if (longest > 1024) {
    m_previewScale = 1024.0 / longest;
    m_previewBase = m_original.scaled(sz * m_previewScale,
                                      Qt::KeepAspectRatio,
                                      Qt::SmoothTransformation);
} else {
    m_previewScale = 1.0;
    m_previewBase = m_original;
}
```

### 5.3 最终提交

```cpp
void CurvesDialog::accept()
{
    // 从对话框模型烘焙最终 LUT
    auto lutR = buildChannelLut(CurveChannel::Red);
    auto lutG = buildChannelLut(CurveChannel::Green);
    auto lutB = buildChannelLut(CurveChannel::Blue);

    // 检查是否真的改动了 —— 没改就不压栈，避免污染历史
    if (isIdentity(lutR) && isIdentity(lutG) && isIdentity(lutB)) {
        QDialog::reject();
        return;
    }

    QApplication::setOverrideCursor(Qt::WaitCursor);

    // 全尺寸运算
    QImage result = Lut::applyToRgb(m_original, lutR, lutG, lutB);

    QApplication::restoreOverrideCursor();

    // 压栈
    auto* cmd = new ImageAdjustCommand(
        m_doc, m_layerIndex, m_original, result, tr("曲线调整"));
    m_doc->commandStack()->push(cmd);

    QDialog::accept();
}
```

> **`ImageAdjustCommand` 复用**：曲线不需要新增 Command 类。它属于"整层快照"这一类操作，和亮度/对比度、滤镜共用 `ImageAdjustCommand`。这正是 `架构规划.md` 里把调整类操作统一成一种 Command 的收益。

### 5.4 拖动性能预算

以 4000×3000 图像为例，目标 60fps（每帧 16ms）的预算分解：

| 阶段 | 耗时 | 说明 |
| --- | --- | --- |
| 烘焙 3 条 LUT | < 0.1ms | 256 × 3 次插值求值 |
| 组装最终 LUT | < 0.02ms | 3 次 256 项查表 |
| LUT 变换（降采样副本） | 3~5ms | 约 100 万像素，单线程 |
| 格式转换（两次） | 2~4ms | ARGB32 ↔ PreMult |
| 控件重绘 | < 1ms | 256 点路径 + 直方图 |
| **合计** | **6~10ms** | 单线程已能满足 60fps |

**结论：拖动预览阶段单线程足够，不需要并行化。** 并行化留给最终的全尺寸运算。

## 7. 边界情况清单

实现时逐条对照检查，这些都是实践中会踩到的：

| 场景 | 期望行为 |
| --- | --- |
| 控制点只有 1 个 | 补上两端点，实际为两点直线 |
| 控制点为 0 个 | 视为恒等曲线 |
| 相邻控制点 x 相同 | 拖动时强制保持 ≥1 间隔；加载数据时去重 |
| 曲线非单调（上下抖动） | 允许 —— 这正是曲线的表达力所在（可做色调分离）。但插值必须用单调样条，避免额外过冲 |
| 端点被拖到中间 | 端点 x 应锁定在 0 和 255，只能改 y |
| 输入图像有 alpha | alpha 通道不变，只变换 RGB |
| 输入图像是预乘格式 | 先转非预乘再运算（见 3.2） |
| 灰度图 | 三个通道 LUT 相同，正常处理 |
| 图像极小（1×1） | 跳过并行分支 |
| 用户没改动就点确定 | 不压栈，直接关闭 |
| 应用时已有选区 | 是否只作用于选区？建议**作用于整层**（与 PS 一致，曲线是全局调整）。若要做选区限制，用 `applyToRgbMasked` |
| 图层被锁定 | 菜单项置灰 |
| 撤销后再打开曲线对话框 | 应从当前图层状态重新计算直方图 |
| 撤销栈到上限 | 曲线操作本身已是整层快照，受 `setUndoLimit(30)` 统一约束 |
