# 图标体系（82 张 SVG）

> 图标只有一个来源（`resources/gen_icons.py`），以及为什么绝不能写 `QIcon(":/icons/x.svg")`。
> 相关实现约束见 [实现铁律.md](实现铁律.md) 第十章。

界面上的每一枚图标都是一张 24×24 的 SVG，**在运行时由 `QSvgRenderer`
显式光栅化**。整套东西由四个部件组成，缺一个就会退化：

| 部件 | 文件 | 职责 |
| --- | --- | --- |
| 生成器 | `resources/gen_icons.py` | 唯一真相：`ICONS` 字典 → 82 张 `.svg` + `resources.qrc` |
| 图标库 | `src/ui/IconLibrary.{h,cpp}` | `icons::icon(name)` / `icons::iconForTool(id)`，带多档尺寸缓存 |
| 自检 | `tests/icon_test.cpp` | 逐图标量像素 + 输出接触表给人眼 |
| 对账 | `tests/action_check.py` ④⑤⑥ | 引用 ⇄ 磁盘 ⇄ qrc 三方一致 |

重新生成（改了 `gen_icons.py` 之后必跑）：

```bash
python resources/gen_icons.py     # 只依赖标准库，不需要 Qt 环境
./run_tests.sh icon               # 重新量一遍 + 刷新接触表
```

### ★ 为什么不能写 `QIcon(":/icons/file_new.svg")` ★

`QIcon` 构造时会去查 Qt 的图标引擎插件链。**如果 `qsvg` 插件在打包时漏了**
（Release 部署最容易漏），它不会报错、不会返回空对象，只会给你一个
**"合法但永远画不出东西"的 `QIcon`** —— `setIcon()` 照单全收，按钮上一片空白，
**0 错 0 警、断言全绿**。

`IconLibrary` 因此改用 `QSvgRenderer` 并检查 `isValid()`，把"能不能画"
变成**可判定**的事，再按三级降级：

```
icons::iconForTool(id)  →  tool->icon()  →  makeLetterIcon(name)
```

最后那级字母占位是必须的：**只有首选没有兜底的话，图标一旦失效就是"空白按钮"，
比字母占位更糟 —— 用户连这是个什么工具都猜不出来。**

### 覆盖范围

| 区域 | 数量 | 说明 |
| --- | --- | --- |
| 工具箱 | 15 个**全部在用** | 阶段六（绘制工具）到此收口：移动 / 画笔 / 橡皮 / 选区 / 裁剪 / 油漆桶 / 吸管 / 直线 / 矩形 / 椭圆 / 抓手 / 缩放 / 文字；阶段七补入 **魔术棒**（`tool_magicwand`）…… 无预留 |
| 菜单 | **57 个有名条目，全部有图** | 含 **4 个带图标的子菜单**（最近打开 / 屏幕截图 / 标尺单位 / 面板）—— **子菜单也是 `QAction`，一样能 `setIcon()`**；屏幕截图那 3 张是 `menu_screen_capture`（子菜单本身）+ `action_screen_capture`（立即截图）+ `action_capture_delay`（三条延迟项**共用**一张沙漏） |
| 图层面板 | 15 个 `layer_*` | 底部 8 个按钮 + 行内的眼睛 / 锁（可见·隐藏、锁·解锁各一张，由三元表达式选名） |
| 视图辅助 | 4 个 `view_*` | `ruler` / `guides` / `guides_lock` / `guides_clear`。「标尺单位」子菜单**自己**带图标（`view_ruler`），它的 5 个单选项**刻意不带** —— 见下 |
| 合计 | **82 张 SVG** | |

工具 id（`QSettings` 持久化的键）→ 图标名的映射写死在 `IconLibrary.cpp` 的静态表里。
**工具 id 不能为了图标好看而改名** —— 改了，用户上次用的工具就丢了。

★ **「标尺单位」的 5 个单选项刻意不设 `objectName`** ★
对账脚本有一条"有名字的菜单动作必须有图标"的规则（`action_check.py` ②）。
把它们牵连进来，就得给 5 个单选项各配一张图标（或共用一个）—— 纯噪音。
定位它们靠**子菜单本身**（`menuRulerUnit` 有 `objectName`）+ `rulermetrics::unitAt(下标)`。
★ 代价要认：这些槽是普通私有成员函数（不是 `slots:`，`QMetaObject::invokeMethod` 也找不到），
所以自检**不能直接调 `setRulerUnit()`**，只能 `menuRulerUnit->actions().at(i)->trigger()` ——
而这反而更强：它顺带把"菜单第 i 项 ⇄ `unitAt(i)`"这根线也钉住了。

### 怎么验证"图标真的画出来了"

三层，缺一层都会漏：

1. **静态对账**（`./run_tests.sh actions`）—— 名字对得上；
2. **量像素**（`./run_tests.sh icon`）—— 每张图不是空白、不是糊块、没被裁角，
   并输出 `tests/build/icons_contact_sheet.png`；
3. **看真实界面**（`.buildlog/shot/` 的一次性截图工具）—— 它有 `menushot` 模式，
   把 8 个下拉菜单**真的 `popup()` 再 `grab()`**，逐个打印"带图标 N/M"：

   ```
   文件(&F) 259×200  带图标 7/7      编辑(&E) 357×200  带图标 7/7
   选择(&S) 307×84   带图标 3/3      … 共 48/48
   ```

   还有 `layers` 模式：走用户路径建三层、每层画一个错开的圆、经面板控件设
   "正片叠底 + 70%"、再经面板信号锁一层隐藏一层，然后 grab **面板单张**与
   **整窗**各一张，并打印自证信息（行序、每行文本、按钮图标缺失数）：

   ```
   图层面板：3 行，活动行 = 1
     第 0 行「隐藏的高光」索引 2
     第 1 行「柔光多边形」索引 1
     第 2 行「底色圆」索引 0
   面板按钮 8 个，其中没有图标的 0 个
   ```

   还有 `shape` 模式：白底上用公开入口 `drawShape()` 画一条红斜线 + 一个蓝描边·淡蓝填充的圆角矩形 + 一个橙色实心椭圆，再打印自证信息（**线中点 = 红 / 矩形边界 = 描边蓝 / 矩形内部 = 填充淡蓝 `(199,225,241)` / 椭圆中心 = 橙 / 椭圆外接矩形左上角 = 白**（这条是"椭圆不是圆角矩形"的分水岭）/ 撤销栈 3 条（三段 = 三条）/ 工具箱 11 个按钮没有一个缺图标），并 grab 出 `shape.png` 与 `shape_toolbox.png`。

   还有 `handzoom` 模式：**对着画布发真实的 `QMouseEvent`**（走 MainWindow → CanvasView → 活动工具 → 信号 → `zoomToRect` 的完整路径），先拖出一个框、**不松手**截一张 `handzoom.png`（能看到黑白双线虚线框），再松手截一张 `handzoom_zoomed.png`（视图放大到框住的那块），并用自证信息钉住整条链路：

   ```
   活动工具: zoom（期望 zoom）
   缩放前: 0.3174（31.7%）
   框选模式: true
   框选矩形(图像坐标): (749, 318) 1639×1198
   缩放后: 0.7048（70.5%）
   缩放比变化: 0.3174 → 0.7048（放大了 2.22 倍）
   视图确实放大了: 是          ← 只看「框选模式 = true」证明不了请求接到了画布上
   工具箱按钮 13 个（其中无图标 0 个）
   ```

   **第 3 层不可替代**：`!a->icon().isNull()` 在"图标名写对了、但 qrc 没编进来"
   的情况下**照样为真**（`QIcon` 会去查文件、查不到就给你一个空的），
   所以只有把菜单真的画出来看像素才作数。

> **接触表（给人看的那张图）不是装饰** ★
> 量化断言能证明"不空白、不糊块、不触边"，**证明不了"它看起来像它该表示的东西"**。
> 实测有三个图标是**只有看图才发现的**：`help_qt` 画成了放大镜（和 `view_zoom_in` 撞形）、
> `tool_eraser` 像个菱形、`color_swap` 三个元素挤成一坨 ——
> 它们的 `inkRatio` 全部合格。
> 后来补上图标后，菜单截图里又看出 `flip_h` / `flip_v` 在 **16px 下长得一模一样**
> （两个浅色三角形糊成一团、把中轴盖住了）。改法：三角形放大到几乎顶满 +
> **一深一浅**，靠"深浅对比 + 中轴方向"在两个维度上区分开。

### 两条图标断言都做过植入验证

一条从没见过红光的断言，和一条被注释掉的断言没有区别。所以这两条不变量
各自植入了一个**真正能改变行为**的 bug（`.buildlog/implant_mainwin_icons.py`，
跑完自动还原并 diff 校验逐字节一致）：

| 植入 | action_check（静态对账） | `mainwin_test` [7] 组 |
| --- | --- | --- |
| **A** 把某个菜单动作的图标名改成 `adjust_levels_TYPO`（模拟"改了名字忘了同步 resources"） | ✓ 红：`[错误] 代码里用了图标 …_TYPO，但 resources/icons/…_TYPO.svg 不存在`，并额外警告 `adjust_levels.svg` 成了孤儿 | ✓ 红：`每个有名字的菜单动作都有图标 —— 缺图标：actionLevels` |
| **B** 丢掉 `iconForTool()`，让工具箱退回字母占位（模拟"接线断了"） | ✗ 抓不到（静态检查看不见"接线"），**这正是它需要 mainwin 测试的原因** | ✓ 红：`工具箱按钮上的图标就是该工具的专用图标` |

合计 **54 通过 / 2 失败**，两条的失败签名互不相同 —— 说明它们盯的不是同一件事。
注意 B 的关键：**字母占位是一个合法的、非空的 `QIcon`**，
所以"`icon().isNull()` 为假"这种弱断言根本抓不住它，必须比 `cacheKey`。

### 改图标时的三个坑

| 坑 | 症状 | 规矩 |
| --- | --- | --- |
| **`.pro` 带 UTF-8 BOM** | `qmake` 直接拒读：`Unexpected UTF-8 BOM` | **`.pro` 不能有 BOM**，而 `.cpp/.h/.md` **必须有** —— 两者要求正好相反 |
| **qrc 前缀是"拼接"** | `prefix="/icons"` + `<file>icons/x.svg` 得到 `:/icons/icons/x.svg` | 用 `prefix="/"`；`rcc --list` **看不出**这个错，只有真的去 `QFile(...).exists()` 才露馅 |
| **截图/子工程漏 `QT += svg`** | 编译期 `C1083: 无法打开包括文件 "QSvgRenderer"` | 这是**好事**（比运行时静默空图标强）；主工程 `.pro` 早就带了 `svg` |
